# 요구사항 정의서 - spec-viewer-doc-modified-date

## 정의
스펙 문서의 진행 상태를 트리에서 훑어보는 spec-viewer 사용자를 위해, 문서 행의 상태 기호 옆에 그 문서 파일의 최종 수정일을 흐리게 보여 주고, 행이 패널 안에 들어가면 시분초까지 함께 보여 주는 기능이다.

## 범위
- **포함**: `.kiro` 모드와 GitHub spec-kit 모드의 트리 패널에서 스펙 아래 문서 행(requirements, design, tasks, research, 그 밖의 문서)에 표시하는 최종 수정일, 파일이 없거나 시각을 알 수 없을 때의 생략, 파일 변경 감지로 트리가 다시 만들어질 때의 날짜 갱신.
- **제외**: 스펙 노드(폴더) 행의 날짜, `--all` 모드 트리와 `.kiro` 하위 그룹(steering 등) 트리의 날짜, 날짜 기준 정렬 변경(기존 최근 갱신 정렬은 `spec.json`의 `updated_at`을 계속 사용), 날짜와 시각 형식 설정, 시각을 줄여 일부만 보여 주는 표시, 문서 패널 상태 표시줄의 파일 정보(이미 수정일시를 보여 줌).
- **인접 기대**: 승인 기호와 진행률 표시(`n/m`)는 지금 그대로 유지된다. 파일 감시와 재스캔 방식은 바꾸지 않으며, 기존 갱신 시점에 날짜도 함께 갱신된다.

## 요구사항

### 1. 문서 행 최종 수정일 표시
- 1.1: [`.kiro` 모드에서 스펙을 펼쳐 문서 행이 보임 + 그 문서 파일이 존재함] 행에 `YYYY-MM-DD` 형식의 최종 수정일이 파일명 뒤에 표시된다.
- 1.2: [GitHub spec-kit 모드에서 기능을 펼쳐 문서 행이 보임 + 그 문서 파일이 존재함] 행에 `YYYY-MM-DD` 형식의 최종 수정일이 파일명 뒤에 표시된다.
- 1.3: [문서 파일이 없어 미생성으로 표시된 행] 날짜 없이 기존 표시 그대로 나온다.
- 1.4: [문서 파일은 있으나 수정 시각을 읽을 수 없음] 날짜 없이 기존 표시 그대로 나오고 오류 메시지는 나타나지 않는다.
- 1.5: [`tasks.md` 행에 진행률(`n/m` 또는 "진행률 없음")이 함께 표시됨] 날짜는 진행률 뒤에 표시된다.
- 1.6: [항상] 날짜는 로컬 시간대 기준 날짜이고 파일명보다 흐리게 보인다.
- 1.8: [날짜가 표시되는 행이 시각까지 포함해도 트리 패널 안에 잘리지 않고 들어감] 날짜 뒤에 공백 한 칸과 로컬 `HH:MM:SS` 시각이 이어서 표시된다.
- 1.9: [시각까지 포함하면 그 행이 트리 패널 폭을 넘음] 그 행은 시각 없이 날짜만 표시되고 문서명과 진행률이 잘리지 않는다.
- 1.7: [항상] 승인 기호(미생성, 미승인, 승인, 상태없음)와 문서 순서는 날짜 표시 전과 같다.

### 2. 갱신 반영
- 2.1: [보이는 문서 파일을 수정하여 파일 변경 감지 또는 수동 새로고침으로 트리가 다시 만들어짐] 해당 행의 날짜가 새 수정일로 바뀐다.
- 2.2: [날짜가 표시된 문서 파일이 삭제되어 트리가 다시 만들어짐] 그 행은 미생성 표시가 되고 날짜가 사라진다.

### 3. 기존 동작 보존
- 3.1: [항상] 스펙 노드 행, `--all` 모드 트리, `.kiro` 하위 그룹 트리의 표시는 변경 전과 같다.
- 3.2: [트리 검색으로 문서 행이 일치함] 일치 강조는 행 전체에 적용되어 날짜 부분도 같은 배경으로 강조된다(날짜 문자열은 검색 대상이 아니다).
- 3.3: [항상] 이 기능은 감시 대상 디렉터리 아래 파일을 만들거나 수정하거나 삭제하지 않는다.
