# 요구사항 정의서 - spec-viewer-files-mode-cursor-scan

## 정의
spec-viewer 사용자가 실행 중 파일 모드로 전환할 때, 시작 경로부터 커서까지를 먼저 보여 주고 나머지를 이어서 채우는 방식으로 지연 없이 로딩하고, `--all` 플래그를 "파일 브라우징 모드"가 분명한 `--files`로 교체하며, 모드 전환 핫키를 vi 관례와 충돌하지 않는 Space로 옮기고, 모드를 왕복해도 각 모드의 커서 위치가 보존되는 변경이다.

## 범위
- **포함**: 파일 모드 진입 시 시작부터 커서까지의 트리 구성, CLI 플래그 `--all` 제거 및 `--files` 도입, 모드 전환 핫키 교체(기존 `m` 해제, Space 바인딩, 도움말 갱신), 모드 왕복 시 스펙 모드/파일 모드 각각의 커서 위치 보존, 사용자가 체감하는 모드 전환 지연의 상한. 기존 `spec-viewer-tree-navigation-modes` 요구사항 1.6(전환 시 트리 초기화)은 왕복 커서 복원으로 대체한다 - 같은 세션에서 같은 뿌리로 돌아오는 경우 복원이 우선하고, 새 뿌리로의 진입은 기존 초기화를 따른다.
- **제외**: 스펙 모드 트리 자체의 로딩 로직, `.kiro`/spec-kit 탐지 규칙, 파일 모드의 정렬 규칙(`spec-viewer-files-mode-sort`가 소유), 파일 모드의 재귀 깊이 상한 자체의 변경, 파일 모드 시작 시(앱 실행 시점)의 스캔 뿌리 결정 규칙(`--files [path]`의 인자 그대로), 기존 `spec-viewer-tree-navigation-modes` 요구사항 1.7(전환 시 문서 패널 초기화)의 변경 - 복원되는 것은 트리 커서뿐이고 문서 패널은 기존 초기화를 유지한다.
- **인접 기대**: 파일 변경 감시(watch) 재시작은 새 스캔 뿌리를 기준으로 수행된다, 상태바의 "watch 라이브/수동" 표시는 새 뿌리에 대한 실제 감시 상태를 반영한다.

## 요구사항

### 1. 파일 모드 진입 시 시작부터 커서까지 보여 주기
- 1.1: [스펙 모드에서 모드 전환 키를 누르고, 트리 커서가 디렉터리 또는 폴더성 노드(스펙, 그룹, 하위 디렉터리)를 가리킴] 앱 실행 시 결정된 시작 경로(커서가 시작 경로 밖이면 시작 경로와 커서를 모두 품는 가장 가까운 상위 디렉터리)를 뿌리로 쓰는 파일 모드 트리가 표시되고(뿌리 바로 아래의 `.kiro` 폴더는 숨김 폴더여도 트리에 포함한다), 트리의 처음부터 해당 노드까지의 항목이 모두 보이며 그 위의 폴더는 모두 펼쳐진 채 해당 노드가 선택된 상태로 들어온다. 커서 뒤의 항목은 첫 화면 이후에 채워질 수 있다.
- 1.2: [스펙 모드에서 모드 전환 키를 누르고, 트리 커서가 파일 노드(문서, 스펙 내부 파일)를 가리킴] 1.1과 같은 뿌리의 파일 모드 트리가 표시되고, 처음부터 그 파일까지의 항목이 모두 보이며 그 위의 폴더는 모두 펼쳐진 채 그 파일이 선택된 상태로 들어온다.
- 1.3: [스펙 모드에서 모드 전환 키를 누르고, 트리에 선택된 노드가 없음] 앱 실행 시 결정된 시작 경로를 뿌리로 쓰는 파일 모드 트리가 표시된다.
- 1.4: [1.1/1.2/1.3이 결정한 뿌리를 디렉터리로 읽을 수 없음] 모드가 전환되지 않고, 상태 메시지로 그 경로를 포함한 전환 실패 사유가 표시된다.

### 2. CLI 플래그 교체
- 2.1: [`m --files [path]`로 실행] 파일 모드로 시작하고, 트리 뿌리는 지정한 `[path]`(생략 시 현재 작업 디렉터리)이다.
- 2.2: [`m --all ...`로 실행] 미지원 플래그 오류 메시지와 함께 비제로 코드로 종료한다.
- 2.3: [`m --help`를 봄] `--files`가 표시되고, `--all`은 어떤 형태로도 표시되지 않는다.

### 3. 모드 왕복 시 커서 보존
- 3.1: [파일 모드에서 모드 전환 키를 눌러 스펙 모드로 전환함, 같은 세션에서 스펙 모드 트리가 과거에 적어도 한 번 표시된 적 있음] 그 세션에서 마지막으로 스펙 모드 트리에 있었던 커서 위치가 복원된다.
- 3.2: [파일 모드에서 모드 전환 키를 눌러 스펙 모드로 전환함, 그 세션에서 스펙 모드 트리가 아직 한 번도 표시된 적 없음] 스펙 모드 트리의 기본 커서 위치(기존 스펙 모드 시작 시의 기본 선택)로 들어간다.
- 3.3: [스펙 모드에서 모드 전환 키를 눌러 파일 모드로 전환함, 같은 세션에서 1번 그룹이 새로 결정한 뿌리의 파일 모드 트리가 과거에 적어도 한 번 표시된 적 있음] 그 세션에서 그 뿌리의 파일 모드 트리에 마지막으로 있었던 커서 위치가 복원되고, 1.2의 파일 선택 규칙은 적용되지 않는다. 뿌리마다 따로 기억하므로 뿌리 A에서 B로 갔다가 A로 돌아오면 A의 커서가 복원된다.
- 3.4: [스펙 모드에서 파일 모드로 전환함, 같은 세션에서 새로 결정된 뿌리의 파일 모드 트리가 한 번도 표시된 적 없음] 이전 실행에서 저장된 커서를 포함해 그 뿌리의 과거 커서는 쓰지 않고, 1번 그룹이 결정한 뿌리와 1.2가 지정한 파일 선택 규칙이 그대로 적용된다.
- 3.5: [모드 전환 자체가 실패해서 트리가 바뀌지 않음(1.4)] 현재 모드의 커서 위치는 전환 시도 이전과 동일하게 유지된다.

### 4. 모드 전환 지연 상한 준수
- 4.1: [1.1 또는 1.2에서 시작부터 커서까지 나열되는 마크다운 파일이 100개 이하] 모드 전환 키를 누른 시점부터 새 트리의 첫 프레임이 터미널에 그려지기까지 100 ms 이내이다.

### 5. 기존 동작 무회귀
- 5.1: [항상] 스펙 모드(.kiro / spec-kit) 트리 로딩, 자동 발견된 하위 폴더 그룹(steering 등) 표시, 문서 패널 렌더링, 파일 변경 감시(watch) 이벤트 처리 로직은 이 기능 적용 전과 동일하다.
- 5.2: [파일 모드가 활성화된 상태에서 트리 패널을 봄] 트리에는 1번 그룹이 결정한 뿌리 아래의 항목만 나열된다.
- 5.3: [파일 모드로 들어가 트리를 탐색함] 트리 아이템 정렬, 깊이 상한, 숨김 파일/.gitignore 처리(1.1의 뿌리 바로 아래 `.kiro` 포함은 예외), 파일 선택 시의 문서 렌더링은 이 기능 적용 전과 동일하다.

### 6. 모드 전환 핫키의 vi 비충돌 교체
- 6.1: [팝업이 열려 있지 않은 상태에서 Space 키를 누름] 모드 전환 키 동작(1번/3번 그룹의 각 규칙)이 그대로 수행된다.
- 6.2: [기존 `m` 키를 누름] 모드가 전환되지 않는다.
- 6.3: [도움말 팝업을 봄] Space가 모드 전환으로 표시되고, `m`은 어떤 동작으로도 표시되지 않는다.
- 6.4: [검색 입력줄 팝업에서 Space 키를 누름] 검색어에 공백 문자가 입력된다.
