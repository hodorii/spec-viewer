# 조사와 설계 결정 - spec-viewer-files-mode-cursor-scan

## 요약
- **기능**: `spec-viewer-files-mode-cursor-scan`
- **조사 범위**: Extension (기존 모드 전환 흐름의 스캔 뿌리, 커서 처리 교체)
- **핵심 발견**:
  - 전환 지연의 원인은 `handle_switch_mode`의 Files 방향이 앱 시작 경로 전체를 `FsTree::scan`으로 걷는 것. `FsTree::scan` 자체는 전달받은 뿌리 아래만 걷으므로 뿌리 선택만 바꾸면 해결된다.
  - `tui-tree-widget` 0.24의 `TreeState`는 `Clone`이 아니므로 커서 보존은 선택 경로(`Vec<NodeId>`)만 따로 저장해야 한다. 펼침 상태는 선택 경로의 조상 prefix로 재생성할 수 있다.
  - 모드 전환은 이미 "reducer가 `Control::SwitchMode` 시그널 -> main이 파일시스템 작업 -> `Action::ApplySourceSwitch`로 보고" 구조라, 커서 파생 로직만 갈아끼우면 된다.

## 조사 기록

### 전환 지연의 실측 원인
- **배경**: `m` 키로 파일 모드 전환 시 체감 ~1초.
- **참고 출처**: `src/main.rs` `handle_switch_mode`(539줄), `src/spec/fs_tree.rs` `FsTree::scan`(66줄).
- **발견**:
  - Files 방향 전환은 항상 `FsTree::scan(start)`를 호출하고 `start`는 앱 시작 경로다.
  - `scan`은 `ignore::WalkBuilder`로 최대 깊이 6까지 전체 하위를 재귀 탐색한다. 트리가 클수록 선형으로 느려진다.
- **시사점**: 비동기화나 캐시 없이도 "스캔할 뿌리를 커서 위치로 좁히는 것"만으로 지연이 사라진다.

### 커서 -> 디스크 경로 매핑의 소재
- **배경**: 트리 선택(`Vec<NodeId>`)을 디렉터리 경로로 바꾸는 규칙이 필요.
- **참고 출처**: `src/spec/mod.rs` `NodeId`(`Spec`/`Doc`/`Dir`/`File`), `TreeSource`(`Kiro`/`SpecKit`/`Files`).
- **발견**:
  - `Spec(name)`/`Doc(name, _)`은 이름으로 `TreeSource` 안에서 스펙 디렉터리를 찾아야 한다. `Dir(path)`/`File(path)`은 경로를 이미 알고 있다.
  - `.kiro` 모드와 spec-kit 모드가 `Spec`/`Doc` 도메인 타입을 공유하므로 한 매핑이 두 모드를 다 커버한다.
- **시사점**: 매핑은 `TreeSource`의 순수 메서드로 `spec` 계층에 두면 app/ui 어디서도 같은 규칙을 재사용한다(SSoT).

### 커서 보존 상태의 형태
- **배경**: 모드 왕복 시 각 모드의 커서 위치 복원(요구사항 3.1~3.5).
- **참고 출처**: `tui-tree-widget` 0.24.1 `src/tree_state.rs`.
- **발견**:
  - `TreeState`는 `#[derive(Debug)]`만 있고 `Clone`이 없다. 내부에 렌더 캐시(`last_area` 등)도 있어 통째로 보존하는 것은 부적절하다.
  - `selected()`는 `&[NodeId]`(단일 선택 경로), `open(path)`/`select(path)`로 상태를 다시 만들 수 있다.
- **시사점**: stash는 `Vec<NodeId>` 선택 경로만 저장하고, 복원 시 조상 prefix를 순서대로 `open()`한 뒤 `select()`한다.

### 모드 전환 핫키의 vi 충돌
- **배경**: 사용자 요청 - 모드 전환 키(`m`)가 vi 관례와 충돌하지 않게 바꾼다.
- **참고 출처**: `src/app/keymap.rs` BINDINGS 전수, `src/app/mod.rs` `handle_popup_key`, vi/vim 키 관례.
- **발견**:
  - `m`은 vi의 mark 설정 키(`m{a-z}`)다. 현재 바인딩된 키 중 `q Tab j k d u f b g G [ ] Enter ? n N r t / T 1 2 3 4 s e m o c` + 방향키를 쓰므로 Space는 미바인딩이다.
  - `M`(shift+m)은 vi의 "화면 중앙 커서" 모션인데 읽기 전용 뷰어 키 모델에 없는 동작이라 충돌이 사실상 없고, 앱의 shift 변형 패턴(g/G, n/N, t/T)과도 일관된다.
  - 팝업(검색 입력줄/TOC/도움말/메시지)은 `handle_popup_key`가 전역 키맵을 거치지 않고 처리한다 - 검색 입력줄의 `Char(c)` 분기가 곧바로 버퍼에 push하므로, Space를 전역 바인딩에 넣어도 검색어 공백 입력이 구조적으로 보존된다.
- **시사점**: 후보는 `M`과 Space로 압축됐고 사용자가 Space를 선택했다. pager 관례(less의 "다음 페이지") 근육기억 오발 위험은 사용자가 감수했다.

### 교차 스펙 대조: 소유 스펙의 전환 시 리셋 요구사항
- **배경**: 커서 복원이 기존 스펙들의 전환 동작 규정과 충돌하는지 확인.
- **참고 출처**: `.kiro/specs/spec-viewer-tree-navigation-modes/requirements.md`.
- **발견**:
  - 그 스펙의 1.6(전환 시 트리의 펼침/선택 상태 초기화)은 이 스펙의 3.1/3.3(왕복 커서 복원)과 정면 충돌한다. 모든 기준이 "모드 전환 키"로 키 불가지적이라 핫키 교체 자체는 충돌이 없다.
  - 그 스펙의 1.7(전환 시 문서 패널 초기화)은 복원에서 문서까지 로드하면 깨진다. 실제 관례를 확인하면 트리에서 j/k 커서 이동은 문서를 로드하지 않고 Enter만 로드한다 - 즉 "선택=문서 로드" 불변식은 존재하지 않는다(초안 설계의 전제가 틀렸다).
- **시사점**: requirements 범위에 1.6 대체를 명시 선언했고, 복원은 트리 커서만 하도록 설계를 고쳐 1.7은 무손상 유지했다.

## 아키텍처 패턴 평가

| 선택지 | 설명 | 장점 | 위험과 한계 | 비고 |
|--------|------|------|-------------|------|
| 커서 기준 뿌리 스캔 | 전환 시 커서가 가리키는 디렉터리만 스캔 | 즉시 로딩, 구현 작음 | 커서가 없으면 시작 경로로 폭이 넓어짐 | 사용자 선택 |
| 전환 결과 캐시 | 최초 1회 스캔 후 메모리 보관, 이후 즉시 복원 | 왕복 두 번째부터 즉시 | 첫 전환은 여전히 느림, 무효화 관리 필요 | 사용자 기각 |
| 비동기 스캔 + 로딩 표시 | 즉시 모드만 바꾸고 백그라운드 스캔 | 체감 지연 없음 | 실제 완료까지 동일, 복잡도 큼 | 사용자 기각 |

### 후속: 커서 폴더만 스캔하는 선택의 교체
- 위 표의 "커서 기준 뿌리 스캔"은 전환 뒤 커서 폴더 하나만 보이고 그 앞의 항목이 사라지는 결함이 드러나 교체했다(pm 경유 사용자 지시, 2026-11-17: 전환된 모드에서 처음부터 현재 커서까지 보여야 하고 커서 앞 내용이 접히거나 사라지면 안 된다).
- 지금 방식: 첫 화면은 시작 경로부터 커서까지만 읽고(커서 앞 항목, 커서의 조상, 폴더 커서는 그 내용), 커서 위의 폴더를 모두 펼친 채 커서를 선택하며, 나머지는 기존 백그라운드 재스캔이 곧이어 채운다. 전환 지연 상한(4.1)의 의도는 유지하되 범위가 "커서 폴더"에서 "시작부터 커서까지"로 넓어졌다.
- 기각안과의 관계: "전환 결과 캐시"는 쓰지 않는다. "비동기 스캔 + 로딩 표시"는 모드만 바꾼 채 빈 화면에서 스캔하는 방식이었고, 지금 방식은 첫 화면이 시작부터 커서까지 완결되어 있어 다르다. 다만 나머지를 백그라운드로 채우는 점은 그 기각안과 겹치므로, 이를 설계 결정으로 확정할지는 사용자 결정을 기다린다(design.md 핵심 결정에는 아직 올리지 않았다).

## 설계 결정

### 결정: `커서 복원 판정을 reducer의 ApplySourceSwitch 핸들러에 둔다`
- **배경**: 복원 우선순위(과거 뿌리 일치 복원 > 커서 파일 선택 > 기본)와 stash 저장 시점이 필요.
- **검토한 대안**:
  1. main이 복원 정보를 `Action` 필드로 전달 - 커서 지식이 main과 reducer에 분산.
  2. reducer가 `ApplySourceSwitch` 처리 시작 시점(리셋 전)의 outgoing 상태에서 직접 계산.
- **선택안**: 2번. stash 저장도 이 시점에 수행.
- **근거**: main은 파일시스템과 watch만 책임지는 기존 구조가 유지된다. reducer는 리셋 전 outgoing 상태에 접근 가능하므로 hint 계산에 필요한 정보를 모두 갖고 있다.
- **득실**: 커서 논리가 한곳에 모이는 대신, reducer 핸들러가 길어진다(헬퍼 함수로 분리).
- **후속 확인**: `ApplySourceSwitch` 테스트가 왕복 전 조합(과거 있/없 x 뿌리 같/다름)을 전부 덮는지.

### 결정: `stash는 선택 경로만, 펼침은 조상 prefix로 재생성`
- **배경**: `TreeState`가 `Clone`이 아니고 요구사항은 "커서 위치"만 요구.
- **검토한 대안**:
  1. `TreeState` 통째 보존 - 불가(Clone 아님)이고 렌더 캐시까지 묻어감.
  2. 선택 경로 + 펼침 목록 통째 보존 - 요구사항 밖 상태까지 저장.
- **선택안**: `Vec<NodeId>` 선택 경로만 저장. 복원 시 조상 prefix를 순서대로 open.
- **근거**: 선택된 행이 화면에 보이려면 조상 펼침이 필요충분하고, 그 정보는 선택 경로 자체에 있다.
- **득실**: 저장이 최소화된다. 사용자가 수동으로 펼쳐둔 다른 폴더는 복원되지 않는다(요구사항이 요구하지 않음).
- **후속 확인**: 복원된 선택의 조상이 실제로 펼쳐져 커서가 화면에 보이는지(E2E).

### 결정: `속성 기반 테스트는 신규 의존성 없이 시드 고정 생성기로`
- **배경**: verification-mapping이 `[항상]` 기준(5.1)의 속성 테스트를 요구. 크레이트에 proptest/quickcheck가 없다.
- **검토한 대안**:
  1. proptest 도입 - 축소(shrink) 자동화, 신규 dev-의존성.
  2. 크레이트 내 시드 고정 픽스처 생성기 - 의존성 없음, 축소는 실패 시드로 수동 재현.
- **선택안**: 2번.
- **근거**: 속성 1건을 위해 빌드 그래프에 크레이트를 추가하는 것은 과하다. 실패 시 시드를 출력해 재현한다.
- **득실**: 의존성 최소화. 자동 축소가 없어 실패 시드 분석이 사람 몫.
- **후속 확인**: 속성 위반이 실제로 발견될 만한 도메인이면 proptest 재검토.

### 결정: `모드 전환 핫키를 Space로 교체한다`
- **배경**: 기존 `m`이 vi의 mark 키와 충돌한다.
- **검토한 대안**:
  1. `M`(shift+m) - vi 충돌 최소, Mode 연상 유지, 앱 shift 변형 패턴과 일관. 단 shift 조합이 한 번 더 걸린다.
  2. Space - 미사용 대형 키, 단 pager 관례(다음 페이지) 근육기억 오발 위험.
  3. `m` 유지 + `M` 추가 - 충돌이 그대로 남아 요청 취지와 어긋난다.
- **선택안**: 2번. 사용자 선택.
- **근거**: 검색 입력 등 팝업 경로가 전역 키맵과 분리되어 있어 공백 입력 회귀가 없고, 잘못 눌러도 다시 Space로 즉시 원복된다.
- **득실**: 한 손 오조작 범위가 가장 넓은 키에 드물게 쓰는 동작이 붙는다. 문서 스크롤은 `f`/PageDown에 그대로 있다.
- **후속 확인**: 도움말/키맵 테스트 전부 Space 기준 갱신, `m`은 미바인딩으로 두고 미래 mark 기능에 예약.

## 위험과 완화
- 커서가 가리키는 경로가 전환 사이에 삭제됨 - 복원/힌트 대상이 새 트리에 존재하는지 검증하고, 없으면 기본 커서로 강등(자연스러운 기능 강등).
- 상대 경로로 시작해 뿌리 비교가 우연히 일치/불일치 - 뿌리 비교는 같은 소스(NodeId 파생 경로 또는 시작 인자)끼리만 비교하므로 일관됨. 혼합 비교가 필요해지면 정규화 도입 시점.
- `--all` 제거가 기존 사용자를 깨뜨림 - 사용자가 명시적으로 clean break를 선택(2.2가 요구사항). README 변경이 완결성의 전부.
- Space가 pager 근육기억(다음 페이지)으로 오발됨 - 사용자가 감수 선택. 오발 시 즉시 원복 가능(토글), 도움말에 명시.
