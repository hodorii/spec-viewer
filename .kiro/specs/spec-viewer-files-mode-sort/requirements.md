# Requirements — spec-viewer-files-mode-sort

## 정의
spec-viewer 사용자를 위해 `--all` 모드(순수 마크다운 디렉터리 트리)에서도 `.kiro` 모드처럼 정렬 키를 순환하며 트리 순서를 바꿀 수 있게 하는 기능이다.

## Boundary Context
- **In scope**: `--all` 모드에서 정렬 키 입력 시 이름/최근 수정 2단 순환, 그 정렬이 실제 트리 형제 순서에 반영되는 것, 정렬 키가 패널 제목에 표시되는 것.
- **Out of scope**: `.kiro`/GitHub spec-kit 모드의 정렬 로직 변경, 새로운 정렬 키 종류 추가, 정렬 방향(오름차순/내림차순) 수동 토글, `--sort` CLI 플래그가 받는 값 목록 자체의 변경, `.kiro` 모드 안에서 자동 발견되는 하위 폴더 그룹(steering 등)의 정렬.

## Acceptance Criteria

### 1. `--all` 모드 정렬 순환
- 1.1: [`--all` 모드에서 정렬 키 순환 키 입력] → 정렬 키가 "이름"과 "최근 수정" 사이에서만 순환함.
- 1.2: [`--all` 모드, 정렬 키가 "이름"] → 같은 폴더 바로 아래의 항목들이 이름 오름차순으로 나열됨.
- 1.3: [`--all` 모드, 정렬 키가 "최근 수정"] → 같은 폴더 바로 아래의 항목들이 파일시스템상 최근에 수정된 순서로(가장 최근이 먼저) 나열됨.
- 1.4: [`--all` 모드로 시작, `--sort`로 `.kiro` 전용 키(phase 또는 진행률)를 지정함] → 오류 없이 "이름" 정렬로 시작함.

### 2. 트리 구조 유지
- 2.1: [`--all` 모드에서 정렬 키를 바꿈] → 폴더와 그 하위 항목의 포함 관계(어느 항목이 어느 폴더 안에 있는지)는 그대로 유지되고, 같은 폴더 안 형제 항목들의 나열 순서만 바뀜.
- 2.2: [`--all` 모드에서 정렬 키를 바꿈] → 그 시점에 펼쳐져 있던 노드와 선택돼 있던 노드는 그대로 유지됨.
- 2.3: [`--all` 모드에서 파일 변경 감지로 트리가 다시 스캔됨] → 그 시점에 활성화돼 있던 정렬 키가 다시 적용됨(임의로 이름순으로 되돌아가지 않음).
- 2.4: [실행 중 스펙 모드에서 전체 모드로 전환함(모드 전환 키)] → 새로 표시되는 전체 모드 트리에도 그 시점의 정렬 키가 적용됨.

### 3. 정렬 키 표시
- 3.1: [`--all` 모드의 트리 패널을 봄] → 패널 제목에 현재 정렬 키(이름/최근 수정)가 표시됨.

### 4. 기존 동작 무회귀
- 4.1: [`.kiro` 모드에서 정렬 키를 순환함] → 기존과 동일하게 이름/phase/최근 갱신/진행률 4단으로 순환하고 정렬 결과도 이전과 동일함.
- 4.2: [항상] → GitHub spec-kit 모드는 이 기능의 영향을 받지 않음.
- 4.3: [`.kiro` 모드에서 자동 발견된 하위 폴더 그룹(예: steering)을 봄] → 그 안의 하위 폴더·파일 나열 순서는 이 기능 적용 전과 동일함.
