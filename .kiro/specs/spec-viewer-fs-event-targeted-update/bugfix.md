# Bugfix — spec-viewer-fs-event-targeted-update

## 정의
spec-viewer 사용자를 위해 파일 시스템 이벤트 발생 시 전체 재구동(resync) 대신 해당 파일/폴더만 갱신하도록 검토·적용하는 성능 버그픽스 스펙이다.

## 재현 절차
1. 환경: `spec-viewer` release 빌드, `m --all ~/w` (실측 환경: `~/w` = git 루트, 최상위 `.gitignore`가 대형 서브프로젝트 디렉터리 몇 개를 제외 → 트리 스캔 대상 md ~4,474개·디렉터리 ~7,844개, 전체 파일 159,276개. `watch::start`는 루트를 재귀 감시 — 트리에 표시되지 않는 `.md` 아닌 파일·무시 규칙으로 제외된 경로의 변화도 이벤트를 발생시킴. `~/w`는 direnv·에이전트·로그 등으로 파일 변화가 항상 일어나는 활성 워크스페이스).
2. 입력: 앱을 띄워두고 조작 없이 5초 대기하며 `/proc/<pid>/stat`으로 CPU 시간 샘플. 대조군으로 `--no-watch` 동일 실행.
3. 관찰 결과:
   - watch ON: 유휴 CPU 코어의 41% (5초간 2.06 CPU-초) — 조작이 없는데도 상시 소모됨.
   - watch OFF(`--no-watch`): 유휴 CPU 0.8% (0.04 CPU-초) — 차이의 전부가 fs 이벤트 처리.
   - 코드 경로 분리: fs 이벤트(300ms 디바운스 배치)마다 `app/mod.rs::resync`가 UI 스레드에서 전체 재구동을 수행 — `--all`은 `FsTree::scan` 전체 재스캔(내부 kept_dirs 필터가 디렉터리×파일 이중 순회), `.kiro`는 `load_snapshot`(전체 재판독)+`build`+`sort`+`refresh_current_doc`(현재 문서 재판독·재렌더). 트리에 표시되지 않는 파일의 변화도 매번 전체 재구동을 유발하며, 이 상시 부하가 네비게이션·스크롤 멈춤(별도 스펙 `spec-viewer-mouse-scroll-freeze`, `spec-viewer-kiro-mode-freeze`)의 배경을 형성함.

## Boundary Context
- **In scope**: fs 이벤트 → 갱신 범위의 결정(전체 resync vs 해당 경로만 갱신), 이벤트의 표시-대상 여부 판별, resync 비용 자체.
- **Out of scope**: 이벤트 소비 후의 렌더 스케줄링(별도 스펙 `spec-viewer-mouse-scroll-freeze`), `--all` 트리 항목 캐시(완료 스펙 `spec-viewer-files-tree-scroll-latency`), watch 시작 지연(완료 스펙 `spec-viewer-watch-startup-latency`), `tui_tree_widget` 내부 비용(외부 크레이트).

## Behaviors

### 1. 현재 동작 (결함)
- 1.1: [`--all` 모드에서 파일 변화가 계속 발생하는 워크스페이스를 열어두고 조작 없이 대기, 항상] → 프로세스가 유휴 상태에서도 CPU 코어의 ~41%(실측)를 계속 소모함 — `--no-watch` 대비 50배 이상.
- 1.2: [트리에 표시되지 않는 파일(마크다운이 아니거나 무시 규칙으로 제외된 경로)의 변화] → 트리 내용은 전혀 바뀌지 않음에도 전체 재스캔·재구성이 매번 수행됨.
- 1.3: [감시 대상의 임의 파일 변화] → 어떤 파일이 바뀌었는지와 무관하게 이벤트마다 전체 재구동(`.kiro` 모드는 전체 스냅샷 재판독+현재 문서 재판독)이 수행됨.

### 2. 기대 동작
- 2.1: [1.1과 동일 조건] → 유휴 CPU가 `--no-watch`와 실질적으로 동일한 수준으로 유지됨.
- 2.2: [1.2와 동일 조건] → 표시 중인 내용에 영향 없는 파일 변화가 전체 재스캔·재구성을 유발하지 않음.
- 2.3: [1.3과 동일 조건] → 표시 대상 파일/폴더에 영향을 주는 변화가 해당 항목만 갱신됨 — 전체 재판독 없이도 트리·문서가 최신 상태로 유지됨.

### 3. 불변 동작 (회귀 방지)
- 3.1: [표시 대상 `.md` 파일의 생성·수정·삭제, 항상] → 트리와 문서가 정확히 최신 내용으로 갱신됨(요구사항 7.1~7.4 유지).
- 3.2: [갱신 후 트리의 선택·펼침 상태, 항상] → 유지됨(요구사항 7.5 "선택 유지").
- 3.3: [`--no-watch` 실행 및 `r` 키 수동 갱신, 항상] → 동작이 그대로 유지됨(요구사항 7.6).
- 3.4: [`--all` 트리 항목 캐시, 항상] → 엔트리가 실제로 바뀐 경우 캐시 무효화·재구성이 정확히 트리거됨(캐시 정확성 회귀 없음, 완료 스펙 2.2/3.1 요건 유지).
