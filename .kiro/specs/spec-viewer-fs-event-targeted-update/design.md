# Design — spec-viewer-fs-event-targeted-update

## 정의
fs 이벤트를 표시 대상 여부로 걸러 실질적으로 표시에 영향을 주는 변화만, 그리고 해당 파일/폴더만 갱신해, 활성 워크스페이스에서 유휴 CPU를 `--no-watch` 수준으로 되돌리는 설계다.

## 원인 (Root Cause)
- `watch::start`(watch/mod.rs 61행)는 루트를 재귀 감시한다 — 트리에 표시되지 않는 `.md` 아닌 파일, 무시 규칙으로 제외된 경로의 변화까지 모두 이벤트를 만든다.
- `app/mod.rs::update`의 `Action::Fs(_)`(415행)는 `event.paths`를 무시하고 항상 `resync`를 호출한다. `resync`(1137행) 주석의 "selective diffing은 명시적으로 범위 밖 — 항상 전체 재구동, 이 크레이트 규모에서는 저렴"이라는 가정이 실측으로 깨진다: `m --all ~/w` 유휴 CPU 41%(watch ON) vs 0.8%(`--no-watch`)(1.1). 표시에 영향 없는 변화도 매번 전체 재구동을 유발하며(1.2), `.kiro` 모드는 어떤 파일이 바뀌었든 매 이벤트마다 전체 스냅샷 재판독+현재 문서 재판독이 수행된다(1.3).
- `--all` 분기의 `FsTree::scan`(fs_tree.rs 58행)은 루트 전체를 다시 걷고 kept_dirs 필터(81~84행)가 디렉터리×파일 이중 순회를 수행한다 — 이벤트 하나에 규모에 비례하는 비용이 매번 발생한다.

## 수정 방식
1. **표시-대상 관련성 게이트**: 디바운스 배치의 `paths`를 검사하는 순수 함수를 둔다. (a) `.md`/`.markdown` 파일의 생성·수정·삭제, (b) 디렉터리의 생성·삭제(하위에 md가 있을 수 있음), (c) 판별 불가(빈 `paths` 등) 중 하나라도 해당하면 갱신 대상으로 간주하고, 그 외(표시되지 않는 파일의 내용 변화 등)는 폐기한다. 게이트는 `app` 소비부에 둔다(`watch`는 감시·전달만 유지).
2. **대상 갱신 적용**:
   - `--all`: 관련 배치에 대해 전체 스캔 대신 `FsTree.entries`에 경로 단위 패치를 적용한다 — 파일 추가는 정렬 순서에 맞는 위치에 삽입하고 필요한 조상 디렉터리를 보충, 파일 삭제는 엔트리 제거 후 md 하위 파일이 없어진 조상 정리, 디렉터리 추가는 해당 하위 트리만 걷어 삽입, 디렉터리 삭제는 하위 전체 제거+조상 정리. `FsTree`의 불변식(경로 정렬 순, kept-dirs 규칙, depth)을 유지하는 순수 함수군으로 구현해 임시 디렉터리 기반 테스트로 고정한다.
   - `.kiro`: 경로→스펙/steering 매핑으로 영향받은 슬라이스만 재판독·재구성하고, 현재 문서는 그 경로가 현재 문서(또는 소속 스펙)에 영향을 줄 때만 재판독한다.
   - **폴백 안전판**: 패치가 정확히 다룰 수 없는 형태(매핑 실패, 판별 불가 배치)는 전체 재구동을 수행한다 — 정확성 우선, 드물게 발생.
3. 게이트와 대상 갱신은 `spec-viewer-kiro-mode-freeze`의 백그라운드 워커(계산/적용 분리) 위에서 수행된다 — 이 스펙은 갱신 "작업량"을, 그 스펙은 "실행 위치"를 담당한다.

**기각한 대안**:
- watch 등록을 md 파일로 제한: notify는 디렉터리 단위 감시라 파일만 감시하면 디렉터리 생성(하위 md 발견 필요)을 놓쳐 7.1~7.4 갱신 정확성이 깨진다.
- 백그라운드 전체 재구동만(spec 2): 프리즈는 줄지만 상시 CPU 소모(41%)는 그대로라 2.1을 만족하지 못한다.

## 검증 속성
- (a) 결함 재현: 수정 전 관련성 없는 배치(예: `.txt` 수정)가 트리에 아무 변화를 일으키지 않으면서도 갱신 작업을 수행함을 상태 무변화+비용 어서션으로 고정한다(1.1/1.2/1.3).
- (b) 기대 동작: 수정 후 무관 배치는 갱신을 유발하지 않고(2.2), 관련 배치는 해당 항목만 갱신되며 전체 재판독이 발생하지 않음을 어서션한다(2.3). 유휴 CPU가 `--no-watch` 수준으로 수렴함을 실기동 샘플로 확인한다(2.1).
- (c) 불변 동작: 표시 대상 변화의 갱신 정확성(생성·수정·삭제가 트리·문서에 반영, 7.1~7.4), 선택·펼침 유지(7.5), `r` 수동 갱신(7.6), `--all` 트리 캐시의 무효화 정확성(완료 스펙 2.2/3.1)이 대상 갱신 경로에서도 통과한다(3.1~3.4).

## 영향 범위
- 변경 파일: `spec-viewer/src/app/mod.rs`(관련성 게이트, 대상 갱신 적용, 폴백), `spec-viewer/src/spec/fs_tree.rs`(경로 패치 함수군), `spec-viewer/src/app/loader.rs`(kiro 슬라이스 재판독). `watch/mod.rs`는 무변경.
- Boundary Commitment 위반 없음: `watch`는 감시·전달만, `ui` 무변경, 패치 함수는 `spec` 계층의 `FsTree` 불변식 내에서만 동작한다.
