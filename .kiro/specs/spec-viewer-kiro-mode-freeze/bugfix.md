# Bugfix — spec-viewer-kiro-mode-freeze

## 정의
spec-viewer 사용자를 위해 `--all`이 아닌 `.kiro` 모드에서 트리 네비게이션·문서 스크롤 중 발생하는 멈춤을 재현·수정하는 성능 버그픽스 스펙이다.

## 재현 절차
1. 환경: `spec-viewer` release 빌드, `--all` 없이 `.kiro` 루트가 있는 프로젝트 열기(실사용 환경: 감시 대상 아래에서 파일 생성·수정이 계속 일어나는 활성 저장소). watch 기본값(Live).
2. 입력: (a) 조용한 상태(파일 변화 없음)에서 트리 네비게이션(화살표·클릭)과 문서 스크롤(`j`/`k`·휠) 수행. (b) 감시 루트 아래 임의 파일을 반복 생성·수정하면서 동일하게 네비게이션·스크롤 수행.
3. 관찰 결과:
   - (a)에서는 네비게이션·스크롤이 즉시 반응함.
   - (b)에서는 조작 도중 UI가 수초간 완전히 멈추고, 멈춤이 풀릴 때 쌓인 입력이 일괄 반영됨 — 같은 조작의 결과가 주변 파일 변화 유무에 따라 달라짐.
   - 코드 경로 분리: fs 이벤트는 300ms 디바운스 배치로 `Action::Fs`가 되고, `app/mod.rs::resync`의 kiro 분기가 UI 스레드에서 `load_snapshot`(루트 아래 전체 재판독)+`build`+`sort`+`refresh_current_doc`(현재 문서 디스크 재판독+마크다운 재렌더)를 매 배치마다 수행함. 이벤트가 연속하면 이 작업이 네비게이션·스크롤 렌더를 계속 뒤로 밀어 멈춤으로 나타남.
   - 참고 실측(같은 `Action::Fs`→`resync` 경로를 공유하는 `--all` 모드): `m --all ~/w` 유휴 CPU 코어의 41% vs `--no-watch` 0.8% — fs 이벤트 처리가 UI 스레드를 지속적으로 점유하는 직접 증거.

## Boundary Context
- **In scope**: `.kiro` 모드에서 fs 이벤트 처리(`resync` kiro 분기의 전체 재판독·재구성 비용)가 UI 스레드를 블로킹하는 것과 네비게이션·스크롤 반응성의 관계.
- **Out of scope**: fs 이벤트의 갱신 범위 선택(전체 resync 대신 해당 경로만 갱신 — 별도 스펙 `spec-viewer-fs-event-targeted-update`), `--all` 모드의 동일 경로(해당 스펙에서 실측 완료), 마우스 모션 이벤트의 렌더 폭풍(별도 스펙 `spec-viewer-mouse-scroll-freeze`), `render_kiro`의 항목 재구성 자체(소규모 트리에서 체감 비용 없음, 기존 주석 참조).

## Behaviors

### 1. 현재 동작 (결함)
- 1.1: [`.kiro` 모드, 감시 대상 아래 파일 변화가 연속 발생하는 동안 트리 네비게이션 또는 문서 스크롤] → UI가 수초간 완전히 멈추고, 멈춤이 풀릴 때 쌓인 입력이 일괄 반영됨.
- 1.2: [동일한 네비게이션·스크롤을 감시 대상에 파일 변화가 없는 상태(`--no-watch` 또는 조용한 저장소)에서 수행] → 멈춤 없이 즉시 반응함 — 조작 반응성이 주변 파일 변화에 의존함.

### 2. 기대 동작
- 2.1: [1.1과 동일 조건] → 파일 변화가 연속 발생해도 네비게이션·스크롤이 즉시 반응함(수초 단위 멈춤 없음).
- 2.2: [1.2와 동일 조건] → 반응성이 주변 파일 변화와 무관하게 일정하게 유지됨.

### 3. 불변 동작 (회귀 방지)
- 3.1: [표시 대상 파일 변화 발생, 항상] → 트리·문서가 최신 내용으로 갱신됨(요구사항 7.1~7.4 유지).
- 3.2: [갱신 후 트리의 선택·펼침 상태, 항상] → 유지됨(요구사항 7.5 "선택 유지").
- 3.3: [현재 열린 문서, 항상] → 갱신 후에도 현재 문서 표시가 유지되고 내용이 바뀐 경우에만 올바르게 다시 렌더됨.
- 3.4: [`--all` 모드, 항상] → 이 수정은 `.kiro` 경로에 적용되며 `--all`의 감시 갱신 동작에 회귀가 없음.
