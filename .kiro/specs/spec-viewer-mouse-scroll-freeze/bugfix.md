# Bugfix — spec-viewer-mouse-scroll-freeze

## 정의
spec-viewer 사용자를 위해 마우스 휠/트랙패드 스크롤이 키보드 화살표와 동일하게 즉시 반영되도록 하는 성능 버그픽스 스펙이다.

## 재현 절차
1. 환경: `spec-viewer` release 빌드. `--all` 모드로 실사용 워크스페이스(실측: `~/w`, 트리 md ~4,474개·상위 디렉터리 9개) 열기. 실마우스/트랙패드 입력이 앱에 도달하는 터미널(에이전트는 `crossterm::event::EnableMouseCapture`로 `?1000h`+`?1002h`+`?1003h`+`?1006h`를 활성화하므로, 포인터가 터미널 위에서 움직이는 동안 `MouseEventKind::Moved` 이벤트가 초당 수십~수백 개 스트리밍됨; tmux는 앱이 요청한 마우스 모드를 패널에 전달).
2. 입력: 문서 패널(우측)에서 (a) 키보드 `↓`/`j` 연속 입력으로 같은 거리를 스크롤, (b) 마우스 휠/트랙패드 관성 스크롤로 같은 거리를 스크롤. (b)는 포인터를 움직이며(클릭 없이) 스크롤하는 실제 사용 자세를 포함.
3. 관찰 결과:
   - (a) 화살표 키는 화면이 입력을 즉시 따라옴.
   - (b) 휠 스크롤은 화면이 수초간 멈춘 뒤 한 번에 몰아서 점프하며 따라오고, 포인터를 함께 움직이면 멈춤이 더 심해짐 — 같은 상태·대상에서 입력 장치에 따라 반응성이 다름.
   - 코드 경로 분리: `main.rs::run_loop`는 이벤트 1개당 리듀서+전체 `terminal.draw` 1회를 동기 수행(배치·병합 없음). `app/mod.rs::handle_mouse`의 `_ => {}`는 `Moved`를 무시하지만 렌더는 `step`에서 항상 수행되므로, 포인터 이동만으로 초당 수백 회의 전체 렌더가 발생. 휠 이벤트 1개는 문서 3행(`scroll_by(±3)`) 또는 트리 `key_down()` 3회를 동반.
   - 참고 실측(키 이벤트 기준): `--all ~/w`에서 트리 펼침 상태 1이벤트당 CPU ~3.5ms — 모션 스트리밍 200/s 가정 시 렌더만으로 코어의 ~70%를 소모하며, 소진 속도보다 이벤트가 빨리 쌓여 지연이 누적됨.

## Boundary Context
- **In scope**: 마우스 휠/모션 이벤트 처리 경로의 렌더 스케줄링(이벤트별 전체 렌더, 배치 없음)이 반응성에 미치는 영향. `main.rs` `run_loop`, `app/mod.rs` `handle_mouse`/`scroll_panel_under_pointer`의 이벤트 소비 경로.
- **Out of scope**: fs 이벤트로 인한 resync 지연(별도 스펙 `spec-viewer-fs-event-targeted-update`), `--all` 트리 항목 캐시(완료 스펙 `spec-viewer-files-tree-scroll-latency`), `tui_tree_widget` 내부 비용(외부 크레이트), 터미널 에뮬레이터/tmux의 마우스 시퀀스 전달 자체의 동작.

## Behaviors

### 1. 현재 동작 (결함)
- 1.1: [마우스 휠/트랙패드로 문서 패널을 스크롤(관성 포함)] → 화면이 즉시 따라오지 못하고 수초간 멈춘 뒤 쌓인 스크롤이 일괄 반영됨 — 같은 거리를 키보드 화살표로 스크롤하면 즉시 따라옴.
- 1.2: [포인터를 패널 위에서 이동(클릭 없이)하며 휠 스크롤] → 포인터가 움직이는 동안 반응 지연이 더 커지고 멈춤이 더 자주·오래 발생함.

### 2. 기대 동작
- 2.1: [1.1과 동일 조건] → 마우스 휠 스크롤이 키보드 화살표 스크롤과 체감상 동일하게 즉시 반영됨(수초 단위의 일괄 점프 없음).
- 2.2: [1.2와 동일 조건] → 포인터 이동 중에도 스크롤 반응이 유지되어 지연이 누적되지 않음.

### 3. 불변 동작 (회귀 방지)
- 3.1: [휠로 트리 패널 스크롤, 항상] → 선택이 3행 단위로 이동하며 활성 패널이 아니어도 동작함(요구사항 9.2 유지).
- 3.2: [마우스 클릭·드래그 제스처(9.1 포커스 이동, 9.4 행 선택, 9.6 분할 드래그, 9.7 선택 드래그+자동스크롤), 항상] → 모두 종전대로 정확히 동작함.
- 3.3: [어느 시점에 입력된 키·마우스 이벤트, 항상] → 멈춤 이후에도 입력이 손실 없이 전부 처리됨(현재 관찰된 큐 잔존 동작 유지).
