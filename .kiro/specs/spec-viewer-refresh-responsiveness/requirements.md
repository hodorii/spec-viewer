# 요구사항 정의서 - spec-viewer-refresh-responsiveness

## 정의
스펙 문서를 편집하며 트리와 문서를 보는 spec-viewer 사용자를 위해, 파일 변경 감지나 수동 새로고침 중에도 화면이 멈추지 않고, 같은 문서를 다시 열 때 즉시 보이며, 좁은 트리 패널에서도 수정일이 읽히게 하는 변경이다.

## 범위
- **포함**: 트리 재스캔(`.kiro`, 파일 모드, spec-kit 세 소스 모두)의 백그라운드 실행과 완료 반영, 같은 문서 재선택 시 렌더 결과 재사용, 보이는 문서 한 개만 바뀐 파일 변경 이벤트의 부분 갱신, 좁은 패널에서 수정일을 `MM-DD`로 줄여 표시.
- **제외**: 파일 감시기 자체와 디바운스 방식(`watch`가 소유), 스캔 알고리즘(`FsTree::scan`의 필터와 정렬), 문서 렌더러(markdown) 내부 성능, 시분초 표시 규칙(`spec-viewer-doc-modified-date` 1.8, 1.9가 소유), 영속 캐시(디스크에 렌더 결과 저장).
- **인접 기대**: 기존 새로고침 동작(정렬 재적용, 선택 유지, 삭제된 문서의 삭제 표시, 스크롤 위치 보존)은 그대로 유지된다. 시작 직후 첫 트리는 지금처럼 동기로 만든다.

## 요구사항

### 1. 재스캔을 백그라운드에서 수행
- 1.1: [파일 변경 이벤트 또는 수동 새로고침 + 재스캔이 진행 중이 아님] 재스캔을 백그라운드에서 시작하고 입력 처리와 화면 그리기는 즉시 계속된다.
- 1.2: [재스캔이 진행 중 + 키나 마우스 입력이 들어옴] 입력은 재스캔 완료를 기다리지 않고 현재 화면 기준으로 처리된다.
- 1.3: [재스캔 완료] 새 트리가 반영되고 활성 정렬 키가 다시 적용되며, 선택과 펼침 상태, 열린 문서의 스크롤 위치가 유지된다.
- 1.4: [현재 뿌리의 재스캔이 진행 중 + 또 다른 변경 이벤트나 새로고침이 들어옴] 재스캔을 겹쳐 시작하지 않고, 진행 중인 것이 끝난 뒤 한 번만 더 수행한다(여러 번 들어와도 한 번).
- 1.5: [재스캔 완료 전에 사용자가 소스 모드를 바꾸거나 스캔 뿌리를 바꿈] 이전 뿌리의 결과는 버려지고 현재 트리에 반영되지 않으며, 대기 중이던 "한 번 더" 요청도 버려진다. 새 뿌리의 재스캔은 이전 스레드의 종료를 기다리지 않고 시작할 수 있다(버려질 결과를 만드는 스레드는 동시 한 개 규칙에서 제외).
- 1.8: [재스캔 중 사용자가 정렬 키를 바꿈] 완료 반영 시점의 현재 정렬 키로 다시 정렬된다.
- 1.6: [재스캔 중 열린 문서가 삭제됨] 완료 반영 시 기존 삭제 표시 규칙이 그대로 적용된다.
- 1.7: [재스캔이 실패하거나 스레드가 비정상 종료] 기존 트리가 그대로 유지되고 프로그램은 종료되지 않으며 다음 이벤트에서 다시 시도된다.

### 2. 문서 렌더 결과 재사용
- 2.1: [같은 경로의 문서를 같은 패널 폭으로 다시 선택 + 파일의 수정 시각과 크기가 마지막 렌더 때와 같음] 파일을 다시 읽거나 렌더하지 않고 이전 결과를 보여 준다.
- 2.2: [파일의 수정 시각, 크기, 패널 폭 중 하나가 달라짐] 새로 읽고 렌더한다.
- 2.3: [파일이 삭제되거나 읽을 수 없게 됨] 캐시 결과를 쓰지 않고 기존 삭제 또는 읽기 오류 표시가 나온다.
- 2.4: [캐시가 상한 개수(16)를 넘음] 가장 오래 쓰이지 않은 항목부터 버려진다.
- 2.5: [재사용된 결과] 상태 표시줄의 수정일, 크기, 줄 수는 새로 읽은 결과와 같은 값이다.

### 3. 부분 갱신
- 3.1: [파일 변경 이벤트의 경로가 하나 이상이고 전부 지금 문서 패널에 일반 문서로 열린(`Rendered`) 같은 파일이고 그 파일이 `spec.json`과 `tasks.md`가 아니며 존재함] 트리를 다시 스캔하지 않고 그 문서만 다시 읽어 보여 주며, 트리 행의 수정일도 새 값으로 바뀐다.
- 3.2: [경로가 없는 이벤트, 수동 새로고침(`r`), 변경 이벤트에 그 밖의 경로가 하나라도 있음, 정의 보기나 메타 오류 보기가 열려 있음, 또는 대상이 `spec.json`이나 `tasks.md`, 또는 파일이 사라짐] 전체 재스캔(1)으로 처리한다.
- 3.3: [부분 갱신 + 문서가 줄어듦] 스크롤 위치가 새 마지막 줄 안으로 조정된다(기존 규칙).

### 4. 좁은 패널의 수정일 축약
- 4.1: [문서 행에 `YYYY-MM-DD` 전체가 들어감] 지금처럼 날짜(와 들어가면 시각)를 표시한다.
- 4.2: [문서 행에 `YYYY-MM-DD`가 전부 들어가지 않지만 `MM-DD`는 들어감] `MM-DD`를 표시한다. 문서명과 진행률은 잘리지 않는다.
- 4.3: [`MM-DD`도 들어가지 않음] 날짜를 표시하지 않고 문서명과 진행률을 우선 보여 준다.
- 4.4: [항상] 일치 강조와 흐림 스타일, 날짜가 없는 행의 표시는 변경 전과 같다.

### 5. 기존 동작 보존
- 5.1: [항상] 재스캔과 캐시와 부분 갱신은 감시 대상 디렉터리에 파일을 만들거나 수정하거나 삭제하지 않는다.
- 5.2: [테스트나 스레드를 쓰지 않는 호출] 재스캔을 동기로 수행하는 방식도 유지되어 기존 동기 테스트가 그대로 통과한다.
