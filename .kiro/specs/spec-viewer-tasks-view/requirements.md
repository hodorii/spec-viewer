# 요구사항 정의서 - spec-viewer-tasks-view

## 정의
spec-viewer 사용자(스펙 작업을 진행/리뷰하는 개발자)를 위해, 방법론 설정이 지정하는 작업 목록 문서(기본값: `.kiro` 모드의 `tasks.md`)를 구조화된 목록으로 보여주고, 그 안의 메타 태그(`_Requirements:_`/`_Boundary:_`/`_Depends:_`/`_BizProcess:_`)를 같은 작업 디렉터리 안의 참조 위치로 바로 이동시키는 뷰어 기능이다.

## 범위
- **포함**: 방법론 설정이 지정한 작업 목록 문서의 구조화된 표시(작업 번호, 체크박스, `(P)`, 메타 태그), 같은 디렉터리 안에서의 크로스 참조 이동(Navigator), 방법론 설정 자체(어떤 파일이 작업 목록인지, 그 파일이 쓰는 태그가 무엇이고 각 태그가 어떤 파일로 이어지는지)의 설정 가능성. `.kiro` 모드의 현재 구성(`tasks.md` + 5개 태그)을 이 설정의 기본값으로 제공한다.
- **제외**: 스펙(작업 디렉터리)을 넘나드는 참조 이동, 작업 목록 문서 자체의 편집(체크박스 토글 등 작성 보조), `.kiro` 외 다른 모드(예: spec-kit)를 위한 기본 설정을 이 스펙 안에서 새로 만드는 것(구조 자체는 설정 가능하게 열어두되, `.kiro` 기본값 하나만 제공), 참조 대상이 다이어그램인 경우 다이어그램 내부 특정 노드까지의 하이라이트.
- **인접 기대**: 기존 `markdown::render`/문서 뷰어 파이프라인은 작업 목록 문서가 아닌 문서에서 전혀 바뀌지 않는다. 문서 내 검색 기능은 구조화된 Tasks 뷰에서도 계속 동작한다(정확한 동작 방식은 설계에서 정함).

## 요구사항

### 1. Tasks 문서 구조화 표시
- 1.1: [방법론 설정이 작업 목록 문서로 지정한 파일(기본값: `.kiro` 모드의 `tasks.md`)을 선택해서 연다] 작업이 번호, 체크박스 상태, `(P)` 표식과 함께 구조화된 목록으로 표시된다
- 1.2: [구조화된 Tasks 뷰가 표시된 상태에서 전용 전환 키를 누른다] 원래의 마크다운 원문 렌더링으로 전환된다
- 1.3: [마크다운 원문 렌더링 상태에서 전용 전환 키를 다시 누른다] 구조화된 Tasks 뷰로 돌아온다
- 1.4: [작업 목록 문서가 아닌 문서를 보는 중에 전용 전환 키를 누른다] 아무 동작도 일어나지 않는다
- 1.5: [작업 목록 문서에 인식 가능한 체크박스 줄이 하나도 없다] 오류로 중단되지 않고 빈 목록이나 안내 문구가 표시된다

### 2. 작업 메타데이터 표시
- 2.1: [작업 줄 아래에 `_Requirements:_`/`_Boundary:_`/`_Depends:_`/`_Difficulty:_`/`_BizProcess:_` 태그가 있다] 각 태그가 작업 설명 본문과 시각적으로 구분되는 배지 또는 서브라인으로 표시된다
- 2.2: [작업 줄에 `(P)` 표식이 있다] 병렬 진행 가능 작업임을 나타내는 표시가 함께 보인다
- 2.3: [작업에 `DONE` 기준 줄 또는 `_DoneWhen:_` 기준 줄이 있다] 두 표기 모두 완료 기준으로 동일하게 인식되어 표시된다

### 3. 크로스 참조 이동 실행 (Navigator)
- 3.1: [`_Requirements:_` 또는 `_Boundary:_` 태그의 조항 번호를 선택해 이동을 실행한다] 방법론 설정이 지정한 대상 파일(기본값: 같은 디렉터리의 `requirements.md` 또는 `bugfix.md`)로 전환되고 그 번호의 조항 줄로 위치가 맞춰진다
- 3.2: [`_Depends:_` 태그의 작업 번호를 선택해 이동을 실행한다] 문서 전환 없이 같은 작업 목록 문서 안에서 그 작업 번호의 줄로 위치가 맞춰진다
- 3.3: [`_BizProcess:_` 태그가 가리키는 제목(이름)을 선택해 이동을 실행한다] 방법론 설정이 지정한 대상 파일(기본값: 같은 디렉터리의 `biz-process.md`)로 전환되고 그 제목 문자열이 있는 줄로 위치가 맞춰진다
- 3.4: [이동 결과로 뷰어가 다른 문서를 보여주게 된다] 트리 패널의 선택 상태도 그 문서로 함께 갱신되어 트리와 뷰어 표시가 어긋나지 않는다

### 4. 참조 실패 안전 처리
- 4.1: [이동 대상 파일이 작업 디렉터리에 존재하지 않는다] 이동이 실패했음을 사용자에게 알리고 현재 화면은 그대로 유지된다
- 4.2: [이동 대상 번호나 제목이 대상 파일 원문 어디에도 없다] 이동이 실패했음을 사용자에게 알리고 현재 화면은 그대로 유지된다

### 5. 방법론 구조 설정 적용
- 5.1: [항상] 어떤 파일이 작업 목록 문서인지(절차), 그 문서가 쓰는 태그가 무엇인지(양식), 각 태그가 어떤 파일로 이어지는지(액션)가 전부 방법론 설정이 결정하는 값이다 - 코드에 고정된 파일명, 태그 목록이 아니다
- 5.2: [항상, `.kiro` 기본 설정 기준] 작업 목록 문서는 `tasks.md`, `_Requirements:_`/`_Boundary:_`->`requirements.md`(또는 `bugfix.md`), `_BizProcess:_`->`biz-process.md`, `_Depends:_`->자기 자신이 기본값으로 적용된다
- 5.3: [프로젝트가 기본값과 다른 작업 목록 문서명이나 태그-파일 매핑을 설정한다] 그 설정대로 Tasks 뷰 전환과 Navigator 이동이 동작한다
- 5.4: [설정 파일이 없거나 특정 항목에 대한 설정이 없다] 5.2의 기본값으로 동작한다
- 5.5: [대상 파일(`value-chain.md`/`biz-process.md` 등)이 과거 형식과 새 형식 중 어느 쪽으로 쓰였든] Navigator는 태그 값 문자열을 원문에서 찾는 동일한 방식으로 양쪽 형식 모두에서 참조 위치를 찾는다 - 형식별 전용 파서를 요구하지 않는다

### 6. 기존 동작 무회귀
- 6.1: [항상] 트리(좌), 뷰어(우) 2패널 레이아웃 구조는 바뀌지 않는다
- 6.2: [작업 목록 문서가 아닌 문서를 열람한다] 기존 마크다운 렌더링과 조작이 이번 기능 이전과 동일하다
- 6.3: [트리 패널에서 작업 목록 문서의 진행률 배지를 본다] 기존과 동일하게 체크박스 평면 집계(`n/total`)로 표시된다
- 6.4: [열람 중인 문서가 방법론 설정의 작업 목록 문서로 지정되지 않았다(기본 설정 기준 `--all` 모드의 일반 마크다운 파일, spec-kit 모드의 파일 등)] 구조화된 Tasks 뷰나 메타 태그 표시가 나타나지 않고 기존 렌더링 그대로 보인다
- 6.5: [구조화된 Tasks 뷰가 표시된 상태에서 문서 내 검색을 실행한다] 검색이 오류 없이 정상 동작한다
