# 조사와 설계 결정 - spec-viewer-tasks-view

## 요약
- **기능**: `spec-viewer-tasks-view`
- **조사 범위**: Extension (light discovery, 외부 라이브러리 신규 없음)
- **핵심 발견**:
  - 문서 설치 지점이 5곳이고 모두 `DocView::Rendered`를 만든다. `Rendered` 소비처(스크롤, 검색, TOC, 상태바)는 변형 추가 없이 구조화 뷰를 그대로 받을 수 있다.
  - 이동 좌표는 렌더된 줄 번호이고 원문 줄과의 대응표가 없다.
  - 설정 파일 개념이 없다. `serde_json`은 이미 의존이고 `toml`은 없다.

## 조사 기록

### 구조화 뷰를 어디서 만들 것인가
- **배경**: 6.5(검색 무회귀)와 6.2(다른 문서 무변화)를 동시에 만족해야 한다.
- **발견**: `ui::doc_panel`, `status_bar`, `popup`, `app::search`가 모두 `Rendered`를 `rendered_of`로 꺼내 쓴다. `DocView` 매칭은 104곳이다.
- **함의**: 새 `DocView` 변형이나 `ui` 단계 치환보다 `app`에서 `Rendered`를 만들어 끼우는 쪽이 변경 면적이 가장 작다.

### 번호와 제목을 원문에서 찾을지 렌더 줄에서 찾을지
- **배경**: brief는 "원문 텍스트 탐색"을 적었다.
- **발견**: `scroll`은 `Rendered.plain` 인덱스다. 줄바꿈과 펜스 렌더로 원문 줄 번호와 달라진다.
- **함의**: 같은 문자열 규칙을 `plain`에 적용한다. 형식별 파서가 아니므로 5.5 의도가 유지된다. 한계: 다이어그램 펜스 안 텍스트가 `plain`에 없으면 탐색 실패로 알린다.

## 설계 결정

### 결정: 설정 형식은 JSON
- **배경**: 설정 파일이 처음 생긴다.
- **검토한 대안**: 1. TOML (신규 의존) 2. JSON (기존 `serde_json`) 3. CLI 플래그
- **선택안**: `<kiro_root>/settings/spec-viewer.json`, 항목 단위 덮어쓰기.
- **근거**: 신규 의존 없음, `position_store`가 이미 JSON 저장을 쓴다. CLI 플래그는 태그 목록 표현에 부적합.
- **득실**: 주석을 못 쓴다. 대신 병합 규칙이 단순하다.
- **후속 확인**: 설정 변경 감시는 하지 않으므로 재시작 안내가 필요한지 사용 후 판단.

### 결정: 링크 값 모양 검증
- **배경**: 실제 작업 목록의 `_Boundary:_`는 설계 컴포넌트 이름이고 요구사항 3.1은 조항 번호를 가정한다.
- **선택안**: `LeadingNumber` 규칙 태그는 값이 번호 모양일 때만 링크로 만든다.
- **근거**: 항상 실패하는 링크를 만들지 않고 평범한 텍스트로 둔다.
- **후속 확인**: `Boundary` 기본 대상 자체가 맞는지는 요구사항 승인 쪽 질문이다(보고에 기재).

## 위험과 완화
- 설치 지점 누락 - `install_doc` 밖에서 `state.doc =`를 쓰지 않는다는 점을 재검증 조건에 적고, 통합 테스트가 5경로를 각각 돈다.
- 링크 이동마다 재렌더 - 문서가 작아 문제 없을 것으로 보지만 성능 확인 항목을 둔다.
- 구형 `L2-D1` ID는 biz-process 본문에 없으면 탐색 실패 - 요구사항이 허용하는 4.2 경로로 알린다.
