# 구현 계획 - spec-viewer-tasks-view

## 정의
spec-viewer 구현자를 위해 design.md 컴포넌트 경계(설정 모델, 작업 목록 파서, Tasks 뷰, Navigator, 리듀서, 배선)를 따라 관찰 가능한 완료 상태 단위로 분해한 구현 계획이다.

- [x] 1. 기반: 설정 모델과 공유 규칙과 샘플
- [x] 1.1 (P) 방법론 설정 모델과 `.kiro` 기본값과 덮어쓰기 병합
  - 실패하는 단위 테스트부터: 기본값 조회, JSON 덮어쓰기(항목 대체, 새 이름 추가, 링크 해제), 항목 누락 시 기본값 유지, 잘못된 JSON 오류
  - 작업 목록 파일명, 태그별 별칭과 링크 규칙(대상 파일 후보, 탐색 방식, 값 분리)을 데이터로만 담고 파싱 로직은 두지 않는다
  - _DoneWhen: 기본값이 tasks.md, 5개 태그의 대상 매핑, DONE 별칭을 돌려주고 병합 단위 테스트가 전부 통과한다_
  - _Requirements: 5.1, 5.2, 5.3, 5.4_
  - _BizProcess: 방법론 구조 설정 반영_
  - _Difficulty: mid_
  - _Boundary: spec::methodology_
- [x] 1.2 (P) 체크박스 인식 규칙을 진행률과 공유 가능하게 추출
  - 실패하는 단위 테스트부터: 체크박스 줄이 상태 3종(완료, 미완료, 선택 미완료)과 나머지 텍스트로 해석되는 것
  - 집계 함수가 이 규칙을 쓰도록 바꾸되 결과는 그대로 둔다
  - _DoneWhen: 기존 진행률 테스트 전부와 새 해석 테스트가 통과하고 집계 결과가 달라지지 않는다_
  - _Requirements: 6.3_
  - _Difficulty: low_
  - _Boundary: spec::progress_
- [x] 1.3 (P) 문서 파일 경로로 트리 노드 경로 계산
  - 실패하는 단위 테스트부터: `.kiro`와 spec-kit 소스에서 스펙 문서 경로가 `[Spec, Doc]` 경로로, 트리에 없는 경로는 `None`
  - _DoneWhen: 소스 종류별 계산과 미존재 폴백 단위 테스트가 통과한다_
  - _Requirements: 3.4_
  - _Difficulty: low_
  - _Boundary: spec (locate_doc_node)_
- [x] 1.4 (P) 샘플 스펙 폴더 데이터
  - 요구사항 조항 번호, 업무프로세스 제목(신형 제목 깊이와 구형 들여쓰기 ID 두 형식), 작업 목록(`_DoneWhen:_`와 `DONE`, `(P)`, 의존, 컴포넌트 이름 형태의 경계, 선택 작업)을 담은 샘플 스펙을 테스트 픽스처로 둔다
  - _DoneWhen: 픽스처 폴더가 `.kiro` 스펙 구조로 읽히고 후속 테스트가 이 폴더를 열어 진행률 집계가 샘플의 체크박스 수와 일치한다_
  - _Difficulty: low_
  - _Boundary: tests/fixtures_

- [x] 2. 코어: 파서, 뷰, Navigator, 설정 읽기
- [x] 2.1 작업 목록 파서
  - 실패하는 단위 테스트부터: 번호, 상태 3종, `(P)`, 제목, 태그(정식 이름과 별칭 DONE), 일반 메모 줄, 들여쓰지 않은 제목과 본문 블록, 체크박스 0개, 빈 입력
  - 체크박스 인식은 1.2의 공유 규칙을 쓰고 태그 이름과 별칭은 설정에서 받는다
  - _DoneWhen: 파서 단위 테스트가 전부 통과하고 샘플 작업 목록에서 작업 수가 진행률 집계의 total과 같다_
  - _Requirements: 1.1, 1.5, 2.3_
  - _BizProcess: Tasks 문서를 구조화된 목록으로 본다_
  - _Difficulty: high_
  - _Boundary: spec::tasks_
  - _Depends: 1.1, 1.2_
- [x] 2.2 (P) Navigator: 링크 값 분리와 대상 파일 선택과 줄 탐색
  - 실패하는 단위 테스트부터: 번호 탐색 경계(3이 3.1 줄에 일치하지 않음), 글머리표와 체크박스와 제목 기호 장식 건너뛰기, 제목 탐색의 제목 우선과 본문 대체, 범위 값은 시작 번호, 구형과 신형 업무프로세스 형식 둘 다에서 일치, 대상 파일 없음과 참조 없음의 오류 종류
  - 렌더된 줄 목록만 입력으로 받는 순수 해석으로 상태를 바꾸지 않는다
  - _DoneWhen: 탐색 규칙과 오류 종류 단위 테스트가 전부 통과한다_
  - _Requirements: 3.1, 3.2, 3.3, 4.1, 4.2, 5.5_
  - _BizProcess: 메타 태그 참조 위치로 이동_
  - _Difficulty: mid_
  - _Boundary: app::navigator_
  - _Depends: 1.1_
- [x] 2.3 Tasks 뷰 렌더와 링크 커서
  - 실패하는 테스트부터: 실제 렌더 버퍼에 작업 줄(상태, 번호, 제목), `(P)` 병렬 표시, 태그 서브라인이 본문과 구분되어 보이는 것, 링크 값은 링크 스타일이고 값 모양이 맞지 않는 태그는 평범한 텍스트인 것, 다음과 이전 링크 선택과 선택 링크 강조, 좁은 폭 줄바꿈, 작업 0개일 때 안내 줄
  - 메이저 작업을 헤딩으로 등록해 헤딩 이동이 작업 단위로 동작하게 한다
  - _DoneWhen: 렌더된 프레임에 작업 줄과 태그 서브라인과 `(P)` 표시가 보이고 링크 선택이 프레임의 강조 스타일로 나타나며 체크박스 0개 문서는 안내 줄이 프레임에 보인다_
  - _Requirements: 1.1, 1.5, 2.1, 2.2, 2.3_
  - _BizProcess: 작업 메타데이터 확인_
  - _Difficulty: high_
  - _Boundary: app::tasks_view_
  - _Depends: 2.1_
- [x] 2.4 (P) 설정 파일 읽기
  - 실패하는 단위 테스트부터: 파일 없음은 기본값과 경고 없음, 일부 항목만 있는 파일은 나머지 기본값, 잘못된 JSON은 기본값과 경고 문자열
  - _DoneWhen: 임시 폴더 기반 단위 테스트 3종이 통과한다_
  - _Requirements: 5.3, 5.4_
  - _Difficulty: low_
  - _Boundary: app::loader_
  - _Depends: 1.1_

- [x] 3. 통합: 리듀서와 키와 배선
- [x] 3.1 문서 설치 지점 단일화와 구조화 뷰 전환
  - 실패하는 테스트부터: 작업 목록 문서를 선택하면 구조화 뷰가 보이고 전환 키로 원문 렌더와 왕복하는 것, 작업 목록이 아닌 문서와 `--all`과 spec-kit에서는 전환 키가 무동작이고 렌더가 이전과 같은 것, 선택과 재스캔과 리사이즈와 부분 갱신 다섯 경로 모두에서 같은 판정이 적용되는 것
  - 상태 필드(설정, 뷰, 전환 플래그)와 설치 함수와 전환 키 바인딩을 더하고 도움말 목록이 자동 갱신되는 것을 확인한다
  - _DoneWhen: 실제 프레임에서 tasks.md 선택 시 구조화 뷰가 보이고 전환 키 입력마다 원문 렌더와 구조화 뷰가 번갈아 보이며 다른 문서 프레임은 기존 골든과 같다_
  - _Requirements: 1.1, 1.2, 1.3, 1.4, 6.1, 6.2, 6.4, 6.5_
  - _BizProcess: Tasks 문서를 구조화된 목록으로 본다_
  - _Difficulty: high_
  - _Boundary: app::mod, app::keymap_
  - _Depends: 2.3_
- [x] 3.2 링크 선택 키와 이동 실행과 트리 동기화
  - 실패하는 테스트부터: 링크 선택 후 Enter로 요구사항 조항과 업무프로세스 제목으로 이동하며 트리 선택이 그 문서로 바뀌는 것, 의존 작업 번호는 문서 전환 없이 그 줄로 스크롤되는 것, 대상 파일 없음과 참조 없음은 메시지 팝업이고 선택과 문서와 스크롤이 그대로인 것, 링크 미선택 상태의 Enter는 기존 선택 동작인 것
  - 이동은 대상 로드와 위치 탐색과 트리 경로 확인이 모두 성공한 뒤에만 상태를 바꾸고 기존 문서 로드 흐름과 스크롤 함수를 재사용한다
  - _DoneWhen: 조항 이동 뒤 프레임이 requirements.md의 그 조항 줄을 보여주고 트리 커서가 그 문서에 있으며 실패 시 프레임이 이동 전과 같고 실패 메시지가 보인다_
  - _Requirements: 3.1, 3.2, 3.3, 3.4, 4.1, 4.2_
  - _BizProcess: 메타 태그 참조 위치로 이동_
  - _Difficulty: high_
  - _Boundary: app::mod, app::keymap_
  - _Depends: 1.3, 2.2, 3.1_
- [x] 3.3 시작과 소스 전환 때 설정 적용
  - 실패하는 테스트부터: Kiro 소스 시작과 소스 전환 때 설정 파일이 반영되는 것(작업 목록 파일명을 바꾼 설정으로 그 파일이 구조화 뷰가 되는 것 포함), 다른 소스 종류에서는 설정이 비는 것, 설정 오류 경고가 메시지 팝업으로 보이는 것
  - _DoneWhen: 덮어쓴 설정의 작업 목록 파일명으로 시작하면 그 파일이 구조화 뷰로 보이고 설정 오류는 시작 화면의 팝업 문구로 보인다_
  - _Requirements: 5.2, 5.3, 5.4_
  - _BizProcess: 방법론 구조 설정 반영_
  - _Difficulty: mid_
  - _Boundary: main_
  - _Depends: 2.4, 3.1_
