# 요구사항 정의서 - spec-viewer-watch-opened-dirs

## 정의
큰 작업 폴더(`~/w` 같은 수만 개 폴더)를 파일 모드로 여는 spec-viewer 사용자를 위해, 파일 변경 감시를 전체 폴더가 아니라 열려 있는 폴더에만 걸어 모드 전환과 시작 지연을 없애는 변경이다.

## 범위
- **포함**: 파일 모드(`--all`, 소스 모드 전환 `m`)의 감시 범위를 "스캔 루트 + 펼친 폴더 + 열린 문서의 폴더"(직속 항목만)로 제한, 펼침/접힘에 따른 감시 추가와 제거, 새로 감시하는 폴더의 따라잡기 재스캔.
- **제외**: 트리 스캔 자체(전체 스캔 유지, 지연 로딩 안 함), `.kiro`/spec-kit 소스의 감시(기존 재귀 유지), 디바운스 방식, 이벤트 처리와 재스캔 로직(`spec-viewer-refresh-responsiveness`가 소유).
- **인접 기대**: 감시되는 폴더 안의 변경은 지금처럼 2초 이내 화면에 반영된다. `--no-watch`와 감시 실패 시 수동 새로고침 표시는 그대로다.

## 요구사항

### 1. 파일 모드 감시 시작 비용
- 1.1: [파일 모드로 시작하거나 `m`으로 전환 + 스캔 루트 아래 폴더가 수만 개] 감시 시작 시간이 폴더 총수에 비례하지 않고, 루트 폴더 한 개만 등록한 비용이다(`~/w`에서 100ms 이내).
- 1.2: [파일 모드 감시 시작] 루트 폴더는 하위로 재귀하지 않고 직속 항목만 감시한다.

### 2. 열린 폴더만 감시
- 2.1: [폴더를 펼침] 그 폴더의 직속 항목을 감시 대상에 추가한다.
- 2.2: [폴더를 접음] 그 폴더를 감시 대상에서 뺀다. 접힌 폴더의 하위에서 펼쳐져 있던 폴더도 접힌 상태(보이지 않음)이므로 함께 뺀다. 단 열린 문서의 폴더는 유지한다(2.4).
- 2.3: [모두 펼침(`ExpandAll`), 저장된 위치 복원, 검색 결과로 조상 펼침] 펼쳐진 모든 폴더가 감시 대상이 된다.
- 2.4: [문서가 열려 있음] 그 문서의 폴더는 접혀 있어도 감시 대상에 포함한다.
- 2.5: [감시 중인 폴더 안의 파일 변경, 생성, 삭제] 기존과 같이 2초 안에 화면에 반영된다.
- 2.6: [감시 대상으로 등록하려는 폴더가 이미 삭제됨 또는 등록 실패] 오류로 처리하지 않고 건너뛰며 상태 표시줄은 `Live`로 유지된다. 다음 동기화 때 다시 시도한다.

### 3. 따라잡기
- 3.1: [초기 감시 시작 이후 새로 감시 대상이 된 폴더가 있음] 감시 구멍 동안의 변경을 반영하도록 전체 재스캔을 한 번 요청한다(진행 중 합치기 규칙 적용). 여러 폴더가 한 번에 추가돼도 요청은 한 번이다.
- 3.2: [시작 직후 또는 소스 전환 직후의 초기 감시 대상 설정] 따라잡기 재스캔을 요청하지 않는다(방금 스캔했음). 단, 파일 모드로의 전환은 첫 화면이 시작부터 커서까지만 스캔하므로 나머지를 채우는 재스캔 한 번을 요청한다(spec-viewer-files-mode-cursor-scan 설계 핵심 결정, 이 규칙의 예외).

### 4. 접힌 폴더의 변경
- 4.1: [접혀 있고 감시되지 않는 폴더 안의 변경] 자동으로 반영되지 않아도 되며, 수동 새로고침(`r`)이나 그 폴더를 펼칠 때(3.1) 반영된다.

### 5. 기존 동작 보존
- 5.1: [`.kiro` 또는 spec-kit 소스] 감시는 지금처럼 `.kiro` 루트 재귀 한 개이며 펼침 상태와 무관하다.
- 5.2: [`--no-watch`] 감시를 시작하지 않고 수동 표시를 그대로 유지한다.
- 5.3: [감시 시작 실패] `Manual` 상태와 사유 표시가 그대로다.
- 5.4: [항상] 감시 동기화는 감시 대상 디렉터리에 파일을 만들거나 수정하거나 삭제하지 않는다.
