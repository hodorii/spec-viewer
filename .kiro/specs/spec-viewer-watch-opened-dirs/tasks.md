# 구현 계획 - spec-viewer-watch-opened-dirs

## 정의
큰 작업 폴더를 파일 모드로 여는 사용자를 위해, 감시 범위를 열린 폴더로 제한하고 펼침 상태와 동기화하는 구현 단위로 나눈 실행 계획이다.

- [x] 1. 감시기 범위와 폴더 집합 동기화
- [x] 1.1 `OpenedDirs` 범위로 시작
  - 실패하는 테스트부터: 새 범위로 시작한 뒤 루트 직속 변경 이벤트는 수신하고 하위 폴더 안 변경은 수신하지 않으며, 하위 폴더 수만 개를 만든 임시 디렉터리에서 시작 시간이 작은 디렉터리와 같은 자릿수다
  - `Watch::Live`가 감시기 래퍼(디바운서, 범위, 현재 감시 집합)를 갖게 하고 기존 시작 함수의 시그니처와 `Recursive` 동작은 유지하며 범위를 받는 시작 함수를 추가한다. `start_with_cache` 반환 타입과 `CountingCache` 테스트를 맞춘다
  - _DoneWhen: 새 테스트와 기존 watch 테스트와 `Watch::Live(_)` 매칭 사용처 테스트가 통과한다_
  - _Requirements: 1.1, 1.2, 5.1_
  - _Difficulty: mid_
  - _Boundary: watch_
- [x] 1.2 폴더 집합 동기화
  - _Depends: 1.1_
  - 실패하는 테스트부터: 추가한 폴더의 변경은 수신하고 뺀 폴더의 변경은 수신하지 않으며, 없는 폴더 추가는 오류 없이 건너뛰고 다음 호출에서 재시도되며, 상대 경로 입력과 심볼릭 링크 루트에서 루트가 새 폴더로 세어지지 않고, 사라졌다 재생성된 폴더가 다시 등록되며, `Recursive` 범위에서는 아무 일도 하지 않는다. 동기화가 감시 대상 디렉터리에 쓰지 않음을 확인한다(감시기 조작만 호출)
  - 입력 경로를 시작 때와 같은 정규화 함수 한 곳으로 정규화한다(SSoT)
  - _DoneWhen: 동기화 테스트가 통과하고 반환값이 새로 등록한 폴더 수와 일치한다_
  - _Requirements: 2.1, 2.2, 2.5, 2.6, 5.4_
  - _Difficulty: mid_
  - _Boundary: watch_

- [x] 2. 원하는 감시 폴더 집합과 동기화 접착
- [x] 2.1 (P) 원하는 감시 폴더 집합 계산
  - 실패하는 단위 테스트부터: Files 모드에서 루트만 있을 때 루트 한 개, 폴더 펼침 후 추가, 조상이 접힌 폴더는 제외, 열린 문서의 폴더는 접혀 있어도 포함하며 열린 문서만 바뀌면 집합이 달라지고, Kiro와 spec-kit 소스는 빈 집합, `ExpandAll`과 위치 복원 후 모든 펼친 폴더 포함
  - 읽기 전용 함수이며 `AppState`를 바꾸지 않는다
  - _DoneWhen: 단위 테스트가 통과한다_
  - _Requirements: 2.1, 2.2, 2.3, 2.4, 5.1_
  - _Difficulty: mid_
  - _Boundary: app_
- [x] 2.2 루프 동기화와 따라잡기
  - _Depends: 1.2, 2.1_
  - 실패하는 테스트부터: 폴더를 펼친 뒤 동기화가 새 폴더를 등록하고 재스캔 요청이 한 번만 가고(여러 폴더 동시 추가도 한 번), 펼침과 열린 문서와 재스캔 반영과 변경 이벤트 처리 중 어느 것도 없으면 동기화가 호출되지 않으며, 시작 후 첫 반복과 소스 전환 직후의 기준선 동기화는 복원된 열린 폴더를 등록하되 재스캔을 요청하지 않는다
  - `app`에 재스캔 요청의 공개 진입점을 두고, `run_loop`가 입력 분기 밖에서 열린 노드 집합과 열린 문서의 변화 또는 재스캔 반영 또는 변경 이벤트 처리를 감지해 동기화하고, `main`의 시작과 `handle_switch_mode`가 소스 종류에 맞는 범위(Files는 `OpenedDirs`, 그 밖은 `Recursive`)로 감시를 시작하며 기준선을 초기화한다. `--no-watch`와 `Manual` 상태에서는 동기화를 건너뛴다
  - _DoneWhen: 통합 테스트와 기존 전체 테스트가 통과한다_
  - _Requirements: 2.3, 2.4, 2.6, 3.1, 3.2, 5.2, 5.3_
  - _Difficulty: high_
  - _Boundary: main, app_

- [x] 3. 실제 실행 검증
- [x] 3.1 `~/w`에서 모드 전환과 반영 확인
  - _Depends: 2.2_
  - release 빌드로 `~/w`에서 `m` 모드 전환 소요 시간을 측정하고(전: 약 857ms), tmux에서 기본 실행(옵션 없음)으로 폴더 펼침 후 파일 생성이 화면에 반영되고 접힌 폴더의 변경은 `r`로 반영됨을 확인한다
  - _DoneWhen: 전환 감시 시작이 100ms 이내이고 위 두 동작이 실제 화면에서 확인된다_
  - _Requirements: 1.1, 2.5, 4.1_
  - _Difficulty: low_
  - _Boundary: main(실행 검증만)_
