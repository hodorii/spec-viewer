# Bugfix - spec-viewer-watch-read-event-loop

## 정의
spec-viewer 사용자를 위해 파일 감시가 켜진 유휴 상태에서 디렉터리가 계속 다시 읽히는 재스캔 되먹임을 재현하고 수정하는 버그픽스 스펙이다.

## 재현 절차
1. 환경: Linux(inotify), `spec-viewer` release 빌드(`m`), `.kiro` 가 있는 프로젝트. v0.14.0 과 그 이전 릴리스에서 동일하게 나타남.
2. 입력: 옵션 없이 `m` 을 실행하고 아무 키도 누르지 않은 채 5초간 `.kiro/specs/<name>` 디렉터리의 inotify OPEN 이벤트를 센다. 비교 대상으로 `m --no-watch` 도 같은 방식으로 센다.
3. 관찰 결과:
   - 기본 실행(감시 켜짐): 5초간 OPEN 13~14회 (초당 약 2~3회)
   - `--no-watch`: 5초간 OPEN 1회 (시작 시 한 번)
4. 부작용 관찰: tasks-view 에서 `l` 로 링크를 선택해도 문서 재설치가 초당 수회 일어나 선택이 곧바로 초기화되어, Enter 로 문서 이동을 할 수 없음. `--no-watch` 에서는 같은 조작이 정상 동작함. tasks-view 실물 실행 중 발견.

## Boundary Context
- **In scope**: `src/watch/mod.rs` 의 감시 이벤트 필터(어떤 이벤트를 `FsEvent` 로 전달할지)와 그 테스트.
- **Out of scope**: 재스캔 로직, 이벤트 디바운스, 감시 범위(`RecursiveMode`/열린 디렉터리 집합), 이벤트 처리(app), `--no-watch` 의 기존 동작.

## Behaviors

### 1. 현재 동작 (결함)
- 1.1: [감시 켜짐, 사용자 입력 없는 유휴 상태, `.kiro` 프로젝트] 5초간 `.kiro/specs/<name>` 디렉터리가 13~14회 열림(`--no-watch` 는 1회) - 디렉터리를 읽는 일이 초당 2~3회 반복됨.
- 1.2: [1.1과 동일 조건] 문서 재설치가 초당 수회 일어나 유휴 CPU 를 계속 소비함.
- 1.3: [tasks-view 에서 감시 켜짐, `l` 로 링크 선택 후] 선택이 곧바로 초기화되어 Enter 로 requirements.md 로 이동할 수 없음.

### 2. 기대 동작
- 2.1: [1.1과 동일 조건] 유휴 시 디렉터리 읽기가 시작 시 한 번뿐이며 이후 늘어나지 않음.
- 2.2: [1.2와 동일 조건] 유휴 상태에서 재스캔과 문서 재설치가 일어나지 않아 CPU 를 쓰지 않음.
- 2.3: [1.3과 동일 조건] `l` 로 선택한 링크가 유지되어 Enter 가 requirements.md 로 이동함(`--no-watch` 와 동일).

### 3. 불변 동작 (회귀 방지)
- 3.1: [감시 켜짐, 외부에서 파일 편집/생성/삭제, 항상] 2초 이내 변경이 감지되어 화면에 반영됨(요구사항 7.1 유지).
- 3.2: [`--no-watch` 지정, 항상] 감시 초기화를 건너뛰고 기존과 동일하게 동작함(요구사항 7.6 유지).
- 3.3: [쓰기가 끝난 파일(편집 저장), 항상] 변경으로 계속 보고됨.
