# Requirements — spec-viewer

## 정의
개발자를 위해 `.kiro/` 스펙·steering 문서를 터미널에서 읽기 전용으로 탐색·열람하게 하는 TUI 뷰어이다.

## Boundary Context
- **In scope**: `.kiro/` 루트 탐지, `--all` 일반 마크다운 폴더 탐색, 마우스 조작(포커스·스크롤·클릭·드래그), 스펙·steering 트리, 상태·승인·inclusion 배지와 진행률, 스펙 정의 표시, 마크다운 렌더링, mermaid 텍스트 다이어그램(flowchart TB·LR, sequenceDiagram, erDiagram, classDiagram, stateDiagram), 문서 내 탐색·검색, 파일 변경 반영, 손상된 스펙 복원력.
- **Out of scope**: 문서 편집, `spec.json` 승인 상태 변경, 웹/HTML 출력, 이미지 렌더링, mermaid 미지원 유형(gantt/pie/mindmap 등) 해석, `.kiro/reference/` 브라우징, 다중 문서 검색, `agw` 통합.

## Acceptance Criteria

### 1. 실행과 루트 탐지
- 1.1: [경로 인자 없음] → 현재 디렉터리부터 상위로 `.kiro/` 탐색 후 루트로 오픈.
- 1.2: [경로 인자 지정] → 해당 경로(또는 하위 `.kiro/`)를 루트로 오픈.
- 1.3: [루트 탐색 실패] → 탐색 경로 포함 오류 메시지 stderr 출력 및 비제로 종료.
- 1.4: [뷰어 오픈] → 트리 패널과 문서 패널의 병렬 표시.
- 1.5: [종료 키 입력] → 터미널 상태 복원 후 종료.
- 1.6: [경로 인자가 마크다운 파일] → 트리 없이 그 파일만 문서 패널 전체 폭으로 오픈(파일 뷰). 루트 탐지는 파일 위치 기준으로 수행해 트리를 켤 때 사용.
- 1.8: [`--all` 옵션] → `.kiro` 없이도 동작: 인자 디렉터리(기본 현재 디렉터리) 아래 모든 마크다운 파일(`.md`, `.markdown`)을 디렉터리 트리로 표시. `.gitignore`·숨김 항목 제외, 깊이 6, 이름순. 1.3 의 루트 탐색 실패는 이 모드에서 적용되지 않음.
- 1.9: [`--all` 트리 노드] → 폴더는 접힘/펼침, 파일은 선택 시 문서 패널에 렌더. 스펙 배지·진행률·정의 표시는 없음(3.x, 4.x 비적용). 파일 변경 감시 루트는 인자 디렉터리(7.x 동일 적용).
- 1.10: [레이아웃 모드 핫키] → 실행 중 네 모드를 핫키로 전환(도움말에 표시): 자동(폭이 넓으면 트리+문서, 좁으면 단일 모드처럼 동작) / 좌측 접기(문서만) / 좌측 펼치기(트리+문서 고정) / 단일 모드(트리만 보이다가 문서를 선택하면 문서 뷰로 전환, Esc 로 다시 트리). `--tree` 옵션은 시작 모드를 정하고 핫키가 이를 덮어씀.
- 1.7: [트리 표시 옵션 `--tree always|auto|hidden|single`] → always: 항상 트리 표시 / auto(기본): 파일 인자면 숨김·디렉터리면 표시·좁은 폭은 8.5 규칙 / hidden: 숨김. 실행 중 토글 키로 표시·숨김 전환.

### 2. 스펙 트리 구성
- 2.1: [`.kiro/specs/` 디렉터리] → 각 폴더를 스펙 노드로 표시.
- 2.2: [스펙 노드 확장] → `requirements`(또는 `bugfix`) → `biz-process` → `design` → `tasks` → `research` 순서로 표시.
- 2.3: [기타 .md 파일] → 상기 표준 문서 뒤에 파일명 순으로 표시.
- 2.4: [필수 문서 누락 — `requirements`/`bugfix` 중 하나, `design`, `tasks`] → 흐린 표시 유지, 선택 시 "아직 생성되지 않음" 메시지 표시.
- 2.5: [`.kiro/steering/` 파일] → 스펙과 분리된 Steering 그룹으로 파일명 순 표시.
- 2.6: [문서 노드 선택] → 해당 문서 내용 문서 패널에 렌더링.
- 2.7: [패널 전환 키] → 입력 대상 패널 전환 및 활성 패널 시각적 구분.
- 2.9: [스펙 트리 정렬] → 정렬 키를 핫키로 순환하고 `--sort` 로 시작값 지정: 이름 / phase / 최근 갱신(spec.json updated_at) / 진행률. 현재 정렬 키가 트리 패널 제목에 표시되고 선택 노드는 정렬 후에도 유지.
- 2.10: [트리 패널 포커스 + 검색 키] → 노드 이름 부분 일치(대소문자 무시)로 첫 일치 노드에 선택 이동·강조, 이전/다음 키로 일치 순환, 접힌 폴더 안의 일치는 펼쳐서 이동, 일치 없음은 상태 표시줄에 표시, Esc 로 해제. 문서 패널의 검색(6.5~6.9)과 같은 키·같은 표시 규칙.
- 2.8: [steering 파일 표시] → front matter `inclusion` 값(`always`/`manual`/`fileMatch`/`auto`, 부재 시 `always`)을 배지로 표시.

### 3. 스펙 상태 표시
- 3.1: [스펙 노드 표시] → `spec.json`의 `phase` 값을 이름 옆에 표시.
- 3.2: [문서 노드 표시] → `spec.json` `approvals`의 대응 키(`requirements`·`bugfix`·`bizProcess`·`design`·`tasks`)로 승인 상태(미생성/미승인/승인됨)를 배지로 표시. `research`·기타 문서는 배지 없음.
- 3.3: [스키마 혼용] → `feature_name` 및 `name` 키를 모두 지원하여 동일하게 표시.
- 3.4: [승인 항목 누락] → "상태 없음"으로 표시하고 정상 동작 유지.
- 3.5: [spec.json 부재/파싱 실패] → 스펙 노드에 경고 배지 표시, 문서 노드는 정상 표시.
- 3.6: [경고 노드 선택] → 파싱 실패 원인을 문서 패널에 표시.
- 3.7: [정상 스펙 노드 선택] → `requirements.md`(또는 `bugfix.md`)의 `## 정의` 본문을 문서 패널에 표시.

### 4. 태스크 진행률
- 4.1: [tasks.md 존재] → 체크박스 집계하여 `완료/전체` 형식으로 표시.
- 4.2: [체크박스 인식] → `[x]`, `[X]`, `[ ]`, `[ ]*` 모두 인식하여 집계.
- 4.3: [체크박스 없음] → "진행률 없음" 표시.
- 4.4: [모두 완료] → 진행률을 완료 강조 스타일로 표시.

### 5. 마크다운 렌더링
- 5.1: [기본 렌더링] → 단락/리스트/인용의 폭 맞춤 줄바꿈 및 들여쓰기 정렬.
- 5.2: [중첩 리스트] → 단계별 들여쓰기 증가로 계층 구분.
- 5.3: [헤딩] → 단계별 구분 스타일 적용.
- 5.4: [표] → GitHub 렌더 형태: 열 폭은 내용 폭(페인 폭까지만), 모든 행 사이 가는 구분선과 열 구분선, 헤더는 굵게 + 구분선으로 강조. 페인 폭을 넘으면 가장 넓은 열부터 축소 + 셀 내 줄바꿈.
- 5.5: [체크박스] → 완료/미완료 구분 기호 표시.
- 5.6: [코드 펜스] → 구문 강조 적용 및 가로 잘림(`…`) 표시.
- 5.7: [mermaid 펜스 — `flowchart`/`graph` TB·LR] → 노드는 박스, 간선은 노드 층 사이 띠에 서로 겹치지 않게 배선된 선으로 표시. 기본 엔진은 폭을 우선해 항상 위→아래로 그린다(LR 선언은 방향만 무시, 참조 mdview 와 동일 출력); 좌→우 배치는 `--diagram-engine builtin`. 간선 라벨 표시, `subgraph`는 테두리 그룹.
- 5.21: [다이어그램 엔진 옵션 `--diagram-engine <이름>`] → 그래프형 mermaid 를 지정 엔진으로 배선. 값은 `dg`·`mdview`·`builtin`(기능 `engine-graphs-tui` 활성 빌드는 `graphs-tui` 포함). 미지정 시 기능 `engine-dg` 이 켜진 빌드에서는 `dg`, 아니면 `mdview`. 엔진이 지원하지 않는 유형·문법은 `builtin` 으로 폴백.
- 5.22: [엔진 비교] → 동일 문서 집합을 사용 가능한 모든 엔진으로 렌더한 스냅샷을 나란히 산출(검토용 파일, 자동 판정 없음).
- 5.20: [간선 배선] → 교차는 `┼`로만 표기하고, 두 층 이상 건너는 간선과 되돌아가는 간선은 우회 경로로 그려져 각 간선의 출발·도착을 눈으로 따라갈 수 있음.
- 5.8: [YAML 프론트매터] → 본문에서 제거.
- 5.9: [CJK 문자] → 2칸 폭 계산으로 줄바꿈 및 표 정렬 유지.
- 5.10: [링크] → 링크 텍스트만 스타일 적용, 주소 숨김.
- 5.11: [이미지] → `[이미지: 대체텍스트]` 형태로 표시.
- 5.12: [강조] → 굵게/기울임/취소선/인라인 코드 각각 구분 스타일 적용.
- 5.13: [터미널 리사이즈] → 새 폭에 맞춰 재렌더링 및 현재 위치 유지.
- 5.14: [mermaid 펜스 — `sequenceDiagram`] → 참여자 열과 생명선, 메시지 화살표·라벨을 선언 순서대로 표시.
- 5.15: [mermaid 펜스 — 미지원 유형 또는 파싱 실패] → 유형명 라벨 + 범용 폴백: 선언 행마다 class 스타일 박스(첫 토큰 = 제목, 나머지 = 본문 구획), 행 사이 `-->`·`->`·`:` 관계는 간선으로 그린 박스 그래프. 박스를 하나도 얻지 못하면 테두리 블록으로 소스 표시.
- 5.16: [다이어그램 폭 초과] → 라벨을 `…`로 축약 → 클래스/엔티티 본문(속성·메서드)을 접어 이름만 표시 → 같은 층의 노드를 폭에 맞춰 여러 행으로 래핑 → 그래도 초과 시 테두리 블록으로 소스 표시.
- 5.23: [폴백 박스 라벨] → 유형명은 실제 다이어그램 종류(classDiagram, erDiagram …)를 표시.
- 5.24: [dg 엔진] → dg 크레이트(~/tools/dg, MIT)를 라이브러리로 바인딩해 flowchart/graph·class·er·state 를 인프로세스 렌더(플레인 텍스트, 캡션 없음); 폭에 맞추지 못하면 5.16 규칙의 소스 박스로 폴백. sequence 는 기존 seq.rs.
- 5.17: [mermaid 펜스 — `erDiagram`] → 엔티티는 속성 목록을 담은 박스, 관계는 카디널리티 기호(`||`, `o{` 등)와 라벨이 붙은 선으로 표시.
- 5.18: [mermaid 펜스 — `classDiagram`] → 클래스는 이름/속성/메서드 구획 박스, 관계는 종류(상속·구성·연관)별 화살표 머리로 표시.
- 5.19: [mermaid 펜스 — `stateDiagram`/`stateDiagram-v2`] → 상태는 박스, `[*]`는 시작·종료 표식, 전이는 화살표와 라벨로 표시.

### 6. 탐색과 검색
- 6.1: [스크롤 키] → 한 줄/반 화면/한 화면/처음·끝 단위 이동.
- 6.2: [헤딩 점프] → `[` / `]` 키로 이전/다음 헤딩으로 이동.
- 6.3: [TOC 호출] → 헤딩 계층 목록 팝업 표시.
- 6.4: [TOC 선택] → 팝업 닫힘 및 해당 헤딩 이동.
- 6.5: [검색 호출] → `/` 키 입력 시 일치 위치 강조 및 첫 일치 이동.
- 6.6: [검색 순환] → 이전/다음 키로 일치 위치 순환 이동.
- 6.7: [검색 실패] → 상태 표시줄에 "일치 없음" 표시.
- 6.8: [검색 옵션] → 대소문자 구분 없이 수행.
- 6.9: [문서 전환] → 기존 검색 강조 해제.
- 6.10: [상태 표시줄] → 경로, 스크롤 위치(%), 활성 검색어 표시.
- 6.12: [파일 정보] → 문서를 표시 중일 때 상태 표시줄에 파일 정보 — 수정일(YYYY-MM-DD HH:MM), 크기(사람이 읽는 단위), 행수 — 를 경로·위치(%)와 함께 표시. 파일 변경 반영(7.1) 시 갱신.
- 6.11: [도움말] → `?` 키 입력 시 전체 키 목록 팝업 표시.

### 7. 파일 변경 반영
- 7.1: [현재 문서 변경] → 2초 이내 자동 재렌더링.
- 7.2: [재렌더링 위치] → 보고 있던 위치 유지 (문서 단축 시 문서 끝 표시).
- 7.3: [메타/태스크 변경] → 트리의 단계·승인 배지·진행률 즉시 갱신.
- 7.4: [구조 변경] → `.kiro/` 아래 파일 추가/삭제 시 트리 갱신 및 선택 유지.
- 7.5: [문서 삭제] → "파일이 삭제됨" 메시지 표시 및 트리 선택 유지.
- 7.6: [감시 불가 환경] → 상태 표시줄에 '감시 불가' 표시 및 `r` 키로 수동 갱신.

### 8. 읽기 전용 및 복원력
- 8.1: [파일 수정 금지] → `.kiro/` 아래 어떤 파일도 생성/수정/삭제하지 않음.
- 8.2: [설정 저장 금지] → 설정/캐시/로그 파일을 `.kiro/` 내부에 생성하지 않음.
- 8.3: [권한 부족] → 읽기 실패 원인 표시 후 다른 문서 탐색 허용.
- 8.4: [비정상 입력] → 비어있거나 비UTF-8 파일은 읽을 수 있는 부분을 표시하고 문제 구간은 대체 문자로 표시.
- 8.5: [극소 폭] → 폭 부족 시 활성 패널 하나만 전체 폭으로 표시 및 전환 키 지원.
- 8.6: [예외 발생] → 터미널 상태 복원 후 stderr에 오류 출력 및 종료.

### 9. 마우스 조작
- 9.1: [패널 위 마우스 클릭] → 그 패널이 활성(포커스)이 되고 시각 구분이 즉시 바뀜.
- 9.2: [패널 위 휠 스크롤] → 마우스 아래 패널이 3행 단위로 스크롤(트리는 선택 이동, 문서는 본문 이동), 활성 패널이 아니어도 동작.
- 9.3: [활성 패널에서 화살표 ↑↓] → 트리는 선택 이동, 문서는 1행 스크롤; PgUp/PgDn·Home/End 는 6.1 과 동일.
- 9.4: [트리 노드 좌클릭] → 해당 노드 선택; 문서 노드면 문서 패널에 로드(2.6 과 동일).
- 9.5: [트리 폴더 노드 좌클릭 또는 ▶/▼ 기호 클릭] → 접힘/펼침 토글.
- 9.6: [패널 경계 좌클릭 드래그] → 트리/문서 폭 비율 조절, 최소 폭 20열 보장.
- 9.7: [문서 패널 내부 좌클릭 드래그] → 드래그 범위의 텍스트가 반전 표시로 선택되고, 포인터가 패널 상/하 경계에 닿으면 그 방향으로 자동 스크롤하며 선택이 확장됨.
- 9.9: [선택 후 마우스 업] → 선택 텍스트(줄바꿈 포함)를 클립보드로 복사(터미널 OSC 52); 다른 곳 클릭 또는 Esc 로 선택 해제.
- 9.8: [마우스 캡처 실패 터미널] → 키보드 조작 전부 정상, 상태 표시줄에 표시 없음(조용히 강등).

### 10. 렌더 품질 기준선 (glow 3.0 대비)
- 10.1: [H1/H2] → 제목 아래 제목 너비만큼 밑줄(H1 `━`, H2 `─`), H3~H6 는 색·굵기로 구분.
